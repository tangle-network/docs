# Build and run assistants on Tangle

Tangle builds hosted AI assistants for businesses, starting with hospitality.
The hospitality preview is designed to turn a guest message into an assigned task and bring overdue work to a person.
The complete request-to-resolution flow is still being verified with a design partner.

Developers use Tangle's [Sandbox](/sandbox), [Router](/gateway), agent runtime, integrations, and evaluation tools to build and run agents.
Agent Builder is becoming the hosted path for creating an assistant and connecting approved channels.
That hosted path is in preview while Builder adopts the shared kit.

## What exists today

- **Sandbox:** an isolated computer for an agent, with files, a shell, and browser access.
- **Router:** one API for model requests across supported providers.
- **Intelligence:** traces and comparisons that help a person inspect an agent run and evaluate a change.
- **Blueprint Agent:** an [in-browser coding workspace](/blueprint-agent/introduction) for building projects with an AI agent.
- **Platform:** one account, API keys, and a shared balance for supported services.

The hosted assistant offer uses these shared components.
A live component does not establish that the complete hosted assistant workflow is ready.

## Who this is for

- **Business operators** evaluating the hospitality assistant preview.
- **Developers** running agents in [Sandbox](/sandbox) or building a hosted assistant in Agent Builder.
- **Teams** inspecting run evidence in [Intelligence](/intelligence).

## Where it goes

The first acceptance proof is a real hospitality request completed from message through task assignment, follow-up, and human escalation when needed.
The protocol is a separate long-term path for operator-hosted services and on-chain settlement.
The managed Sandbox and Router services are live today.
