# Model Fallbacks

Specify backup models that are tried in order if the primary model fails or is unavailable.

## Configure fallback models

Pass a `models` array in `providerOptions.gateway`:

```json
{
  "model": "openai/gpt-4o-mini",
  "messages": [{"role": "user", "content": "Hello"}],
  "providerOptions": {
    "gateway": {
      "models": ["google/gemini-2.5-flash", "deepseek/deepseek-v4.1-flash"]
    }
  }
}
```

The gateway tries:

1. `openai/gpt-4o-mini` (primary model)
2. `google/gemini-2.5-flash` (first fallback)
3. `deepseek/deepseek-v4.1-flash` (second fallback)

The response comes from the first model that succeeds.

## Each model runs the full routing chain

For each model in the list, the gateway runs the full routing chain:

1. **Operators** - try operators serving this model (if available)
2. **Direct provider** - call the provider API directly

If both tiers fail for a model, the gateway moves to the next model in the list.

## Combining with provider ordering

Use `models` with `order` to control both model fallback and provider preference:

```json
{
  "model": "openai/gpt-4o-mini",
  "providerOptions": {
    "gateway": {
      "models": ["deepseek/deepseek-v4.1-flash"],
      "order": ["fireworks", "openrouter"]
    }
  }
}
```

This tries:

1. `openai/gpt-4o-mini` via available providers
2. `deepseek/deepseek-v4.1-flash` via Fireworks first, then OpenRouter

## Observability

When fallbacks occur, the [routing trace](/gateway/routing-trace) shows every model and provider attempted:

```
X-Tangle-Routing-Trace: openai/gpt-4o-mini[openai(err:5001ms)], google/gemini-2.5-flash[google(200:1847ms)]
```
