# Use a sandbox from MCP clients

There are two ways to reach a sandbox over the Model Context Protocol:

| Path | Tools | Runs |
|---|---|---|
| Local stdio server | Run code, run commands, read, write, list and search files. | On your machine: `tangle mcp serve` or `createMcpServer(box)`. |
| Hosted computer-use endpoint | Computer use: control the sandbox's desktop. | In the sandbox, over HTTPS with a scoped token. |

## Serve sandbox tools from your machine

`tangle mcp serve` starts an MCP server on stdio for one sandbox. Your MCP
client starts it as a command.

```bash
npm install -g @tangle-network/sandbox-cli @modelcontextprotocol/sdk
tangle sandbox create --name mcp-box
```

The CLI loads `@modelcontextprotocol/sdk` when the server starts, so install
it where the CLI can import it.

Add the server to your client. Claude Desktop and Cursor use the same shape:

```json
{
  "mcpServers": {
    "tangle-sandbox": {
      "command": "tangle",
      "args": ["mcp", "serve", "mcp-box"],
      "env": { "TANGLE_API_KEY": "sk-tan-..." }
    }
  }
}
```

| Client | Config file |
|---|---|
| Claude Desktop | `claude_desktop_config.json`, under Settings, Developer |
| Cursor | `.cursor/mcp.json` in the project, or `~/.cursor/mcp.json` |
| Zed and others | The client's MCP server settings, with the same command, args and env |

| Flag | Default | Effect |
|---|---|---|
| `--session <id>` | `mcp-local` | The kernel session. Variables in `sandbox_run_code` persist for that session. |
| `--name <name>` | `tangle-sandbox` | The server name the client shows. |

The server stops when the client closes its stdin. The sandbox keeps running;
delete it with `tangle sandbox delete mcp-box --force` when you are done.

The tools are `sandbox_run_code`, `sandbox_exec`, `sandbox_read`,
`sandbox_write`, `sandbox_list` and `sandbox_search`, the same set as the
[framework tool packs](/sandbox/integrations#agent-framework-tool-packs). A
failed call returns an MCP result with `isError: true` and the message.

### Build the server in your own program

`createMcpServer(box, options)` returns `{ server, connect, close }`. Use it
when your program picks the sandbox or the tools:

```ts
import { Sandbox } from "@tangle-network/sandbox";
import { createMcpServer } from "@tangle-network/sandbox/agent";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const client = new Sandbox({
  apiKey: process.env.TANGLE_API_KEY!,
  baseUrl: "https://sandbox.tangle.tools",
});

const box = await client.get(process.env.SANDBOX_ID!);
if (!box) throw new Error(`Sandbox ${process.env.SANDBOX_ID} not found`);

const { connect } = await createMcpServer(box, {
  sessionId: "claude-desktop",
  allow: ["sandbox_run_code", "sandbox_read"],
});
await connect(new StdioServerTransport());
```

Point the client's `command` at `node` and this file, with `TANGLE_API_KEY`
and `SANDBOX_ID` in `env`. Without `sessionId`, every caller shares one default
kernel, so give each client its own session.

## Control the sandbox desktop over MCP

A sandbox created with the desktop capability serves computer use as MCP tools
over HTTPS. Create it with `capabilities: ["computer_use"]`, or turn on
**Enable remote desktop** when you create a sandbox in the
[dashboard](https://sandbox.tangle.tools/dashboard). The desktop needs an image
that includes it.

```ts
import { writeFileSync } from "node:fs";
import { Sandbox } from "@tangle-network/sandbox";

const client = new Sandbox({
  apiKey: process.env.TANGLE_API_KEY!,
  baseUrl: "https://sandbox.tangle.tools",
});

const box = await client.create({
  capabilities: ["computer_use"],
  resources: { memoryMB: 4096 },
});
const endpoint = await box.getMcpEndpoint({ ttlMinutes: 60 });
writeFileSync("mcp.json", JSON.stringify(endpoint.config, null, 2));
console.log(endpoint.url, endpoint.expiresAt);
```

`endpoint.config` is a standard `mcpServers` block with an HTTP entry: the
sandbox's `/mcp` URL and an `Authorization` header. Paste it into any MCP
client that speaks the HTTP transport.

| Field | Meaning |
|---|---|
| `url` | The sandbox's MCP endpoint. |
| `authToken` | A short-lived token limited to the requested capabilities. |
| `expiresAt` | When the token expires. Call `getMcpEndpoint()` again for a new one. |
| `serverName` | The entry name in `config`, `tangle-sandbox` unless you pass `serverName`. |
| `capabilities` | What the token may do: `["computer_use"]`. |

The token works only on the MCP endpoint. The sandbox's command and file routes
refuse it, so handing it to a client grants computer use and nothing else.
The desktop shares the sandbox's memory, so size `resources.memoryMB` for the
desktop plus your workload. Delete the sandbox when you are done.

The REST call is `GET /v1/sandboxes/{id}/mcp?capabilities=computer_use`.
Python has no `getMcpEndpoint`; call that route with
`client.fetch("GET", f"/v1/sandboxes/{box.id}/mcp?capabilities=computer_use")`.

## Give coding agents in the sandbox MCP servers

To give Claude Code, Codex or OpenCode inside the sandbox extra MCP servers,
list them in the agent's [AgentProfile](/sandbox/cloud-agents-profiles). To
give them accounts such as GitHub or Gmail, use
[connections](/sandbox/connections).

For retries and duplicate tool calls from an MCP client, see
[Retries and duplicate work](/sandbox/integrations#retries-and-duplicate-work).
