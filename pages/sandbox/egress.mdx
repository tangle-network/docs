# Control network access

Decide which hosts a sandbox can reach, change that while it runs, and see what it tried to reach. The proxy inside the sandbox enforces the policy, and the host firewall backs it.

| Mode | The sandbox can reach |
|---|---|
| `open` | Any host. |
| `strict` | The hosts in `allowDomains`, plus the model endpoint and providers the platform provisioned into the sandbox. |
| `blocked` | No outbound internet. |

Every mode, `blocked` included, reaches the Tangle control plane without listing it: `sandbox.tangle.tools` and its exec origins, `router.tangle.tools` for model calls, and the Hub and workflow routes on `id.tangle.tools`. A sandbox can create sibling sandboxes or publish a preview link under any policy.

## What a sandbox reaches by default

A sandbox created without a policy runs `strict` plus a built-in list of developer hosts:

- package registries: npm, Yarn, PyPI, crates.io, RubyGems and the Go proxy;
- git hosts: GitHub (including `codeload.github.com` and `**.githubusercontent.com`), GitLab and Bitbucket;
- container registries: GitHub Packages, `ghcr.io` and Docker Hub;
- CDNs: `*.cloudflare.com` and `**.fastly.net`;
- the model endpoints the platform provisioned.

A team sandbox created without a policy inherits the team's default policy. `open` is honored only when you or your team set it on purpose; it is never the fallback.

<Callout type="info">
An explicit `strict` policy drops the built-in list. `npm install` then fails unless you list the registry, or add `includeImplicitDomains: true` to keep the list.
</Callout>

### Domain patterns

| Pattern | Matches |
|---|---|
| `api.github.com` | That host only. |
| `*.githubusercontent.com` | `githubusercontent.com` and every subdomain at any depth. |
| `**.githubusercontent.com` | Subdomains only, not `githubusercontent.com` itself. |

`includeImplicitDomains: true` merges the built-in list into a strict policy. That list includes `github.com`, `gist.github.com` and `gitlab.com`, which makes any public repository readable and a gist an allowed destination, so keep it to trusted development sandboxes.

The number of `allowDomains` entries is capped; see [Limits](/sandbox/limits).

### Private addresses

A host that resolves to a private or CGNAT address is refused unless you name the ranges it may use. The exception applies only to that domain and those exact ranges, not to other domains at the same address.

```ts
await box.egress.update({
  mode: "strict",
  allowDomains: [
    "api.github.com",
    { domain: "build.internal", allowPrivateIps: ["10.203.1.0/24"] },
  ],
});
```

## Change the policy while the sandbox runs

```ts
const { policy, source } = await box.egress.get();
console.log(policy.mode, source); // source: "sandbox", "team" or "platform"

await box.egress.update({ mode: "strict", allowDomains: ["registry.npmjs.org"] });
```

`update()` restarts the sandbox's proxy, which interrupts outbound connections for a few seconds and starts a new activity window. Read `denials()` and `activity()` before you change the policy.

### Install, then cut the network

Untrusted code should run without network access. Install under a strict policy, then switch to `blocked`:

```ts
await box.exec("cd app && npm ci");
await box.egress.update({ mode: "blocked" });
const result = await box.exec("cd app && npm test");
```

## Build an allowlist from what was refused

A refused request gets a `403` whose JSON body names the cause:

```json
{"code":"EGRESS_DOMAIN_NOT_ALLOWED","host":"github.com","policy":"allowlist","nextStep":"Add github.com to egressPolicy.allowDomains"}
```

`policy` is the proxy rule that refused it: `allowlist`, or `secrets` for a credential the proxy would not hand over. `box.egress.denials()` lists every refused host, newest first, with how often. Start strict with nothing allowed, run the build once, and read the refusals:

```ts
const box = await client.create({ egressPolicy: { mode: "strict", allowDomains: [] } });
await box.exec("git clone --depth 1 https://github.com/tangle-network/sandbox-demo demo && cd demo && npm ci");

for (const denial of await box.egress.denials({ limit: 50 })) {
  console.log(`${denial.host}  refused ${denial.count}x by ${denial.rejectedBy}`);
}
```

Then allow the hosts you trust:

```ts
await box.egress.update({
  mode: "strict",
  allowDomains: ["github.com", "codeload.github.com", "registry.npmjs.org"],
});
```

## Prove what a sandbox reached

`denials()` is best effort: an empty list can mean nothing was refused or that the proxy log could not be read. For an audit or a benchmark control arm, use `activity()`. It lists allowed and refused hosts and says whether the record is complete.

```ts
const activity = await box.egress.activity({ limit: 500 });
if (!activity.complete) {
  throw new Error(`incomplete record: ${activity.incompleteReasons.join(", ")}`);
}
for (const destination of activity.destinations) {
  console.log(destination.action, destination.host, destination.count);
}
```

An empty `destinations` list with `complete: true` is evidence the sandbox reached nothing. With `complete: false` it proves nothing. `activity()` answers `409` when egress control is not enabled for the sandbox.

`box.egress.usage({ month })` returns the sandbox's egress bytes and charge for a calendar month. Rates are on [Pricing](/sandbox/cost).

## Keep credentials out of the sandbox

A secret can stay with the egress proxy: the sandbox holds a placeholder, and the proxy puts the real value on requests to the hosts you name. Store it with its hosts and select it by name:

```ts
await client.secrets.create("HF_TOKEN", process.env.HF_TOKEN!, { hosts: ["huggingface.co"] });

const box = await client.create({
  secrets: ["HF_TOKEN"],
  egressPolicy: { mode: "strict", allowDomains: ["huggingface.co"] },
});
await box.exec(`curl -s -H "Authorization: Bearer $HF_TOKEN" https://huggingface.co/api/whoami-v2`);
```

A strict policy does not reach the secret's host for you; list it in `allowDomains`. From the CLI, select a proxy-held secret at create with `--proxy-secret '<json>'`. How each custody mode works, the presentation types and what the proxy masks in responses are on [Secrets](/sandbox/secrets).

## Coding agents behind a strict policy

A coding agent's model calls go to the endpoint provisioned into the sandbox, which strict mode allows. When the agent uses your own subscription or a coding plan endpoint, list that provider's host:

```ts
egressPolicy: {
  mode: "strict",
  allowDomains: ["api.anthropic.com", "registry.npmjs.org", "github.com"],
}
```

See [Run a coding agent in a sandbox](/sandbox/cloud-agents) for the agent side.

## REST routes

```bash
curl -X PATCH "https://sandbox.tangle.tools/v1/sandboxes/$SANDBOX_ID/egress" \
  -H "Authorization: Bearer $TANGLE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"mode":"strict","allowDomains":["registry.npmjs.org"]}'
```

| Route | Purpose |
|---|---|
| `PATCH /v1/sandboxes/{id}/egress` | Change the policy on a running sandbox. The body merges into the current policy. |
| `GET /v1/sandboxes/{id}/egress/denials` | Refused hosts, newest first. |
| `GET /v1/sandboxes/{id}/egress/activity` | Allowed and refused hosts, with completeness. |
| `GET /v1/sandboxes/{id}/egress/usage` | A month's egress bytes and charge. |
| `PUT /v1/teams/{id}/egress` | The team's default policy (team owners and admins). |

## Python

Python has `egress_get()`, `egress_update(EgressPolicy(mode, allow_domains, include_implicit_domains))` and `egress_denials(limit)`. It has no `activity` or `usage`, and `EgressPolicy` has no private-address entries. Read them with `client.fetch`, which returns the raw response and does not raise on an error status:

```python
response = client.fetch("GET", f"/v1/sandboxes/{box.id}/egress/activity", params={"limit": 500})
activity = response.json()["activity"]
print(activity["complete"], activity["destinations"])
```
