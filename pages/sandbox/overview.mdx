# Tangle Sandbox

Tangle Sandbox gives your application and your coding agents isolated Linux sandboxes.
Create one in a call, run commands and coding agents in it, keep or fork its disk, and delete it when the work is done.

## What you can do in a sandbox

| Task | Where to read |
|---|---|
| Run shell commands, long-running processes and Python, Node, TypeScript or Bash code | [Run commands and code](/sandbox/commands) |
| Run a coding agent such as Claude Code, Codex or OpenCode on a task | [Run a coding agent](/sandbox/cloud-agents) |
| Drive a coding agent's own terminal UI inside the sandbox, from your terminal or a browser | [Interactive mode](/sandbox/interactive) |
| Read, write, upload and download files | [Files](/sandbox/files) |
| Clone repositories, commit and push | [Git](/sandbox/git) |
| Share a web server running in the sandbox through a public preview link | [Ports and preview links](/sandbox/ports-previews) |
| Snapshot a sandbox, restore it, or fork a running sandbox into copies | [Snapshots and forks](/sandbox/snapshots) |
| Limit which hosts the sandbox can reach | [Network access](/sandbox/egress) |
| Give a coding agent a desktop it can see and control (computer use) | [MCP clients](/sandbox/agents-mcp) |
| Open a shell over SSH or a terminal in your own app | [Shells and terminals](/sandbox/terminals) |
| Run the same work across many sandboxes | [Fleets](/sandbox/agents-fleet) |
| Attach a GPU for a fixed time and spend cap | [GPU leases](/sandbox/gpu-leases) |

The coding agents a deployment offers come from the API, not from this page. List them with `client.listBackends()` in TypeScript, or `GET /v1/backends` from Python, the CLI or any HTTP client:

<Tabs items={["TypeScript", "Python", "CLI"]} storageKey="sandbox-lang">
<Tabs.Tab>

```ts
const { backends } = await client.listBackends();
for (const backend of backends) console.log(backend.type, backend.name);
```

</Tabs.Tab>
<Tabs.Tab>

```python
response = client.fetch("GET", "/v1/backends")
for backend in response.json()["backends"]:
    print(backend["type"], backend["name"])
```

`client.fetch` sends an authenticated request and returns the raw response without raising on an error status.

</Tabs.Tab>
<Tabs.Tab>

```bash
curl -s https://sandbox.tangle.tools/v1/backends \
  -H "Authorization: Bearer $TANGLE_API_KEY"
```

</Tabs.Tab>
</Tabs>

Each entry says whether the agent runs only on your own credential (`callerCredentialOnly`) and what it supports, such as streaming, MCP and sessions.

## Four ways to use it

| Way in | Install | Reference |
|---|---|---|
| TypeScript SDK | `npm install @tangle-network/sandbox` | [TypeScript SDK](/sandbox/sdk-typescript) |
| Python SDK | `pip install tangle-sandbox` ([PyPI](https://pypi.org/project/tangle-sandbox/)) | [Python SDK](/sandbox/sdk-python) |
| CLI, the `tangle` command | `npm install -g @tangle-network/sandbox-cli` | [CLI](/sandbox/cli) |
| REST API at `https://sandbox.tangle.tools` | Any HTTP client | [REST API](/sandbox/api-reference) |

All four call the same API with the same account key, so a sandbox created from one can be used from the others.
The dashboard at [sandbox.tangle.tools/dashboard](https://sandbox.tangle.tools/dashboard) shows the same sandboxes; see [Dashboard](/sandbox/web-app).

Never run bare `npx tangle`: that npm name belongs to an unrelated package. Use `npx @tangle-network/sandbox-cli`.

The Python SDK covers creating, running and deleting sandboxes, files, git, prompts, snapshots, egress rules, fleets and batches.
Interactive terminals, preview links, sessions and GPU leases are TypeScript, CLI or REST only; each guide names the path to use.

## The parts of a sandbox

Each term has a full explanation in [How sandboxes work](/sandbox/concepts).

- **Sandbox**: an isolated Linux workspace with its own filesystem, network policy, size and lifetime.
- **Coding agent**: the agent installed in a sandbox, such as Claude Code, Codex or OpenCode. Pick it with `backend.type`.
- **AgentProfile**: the agent's model, instructions, tools, MCP servers and permissions. See [AgentProfiles](/sandbox/cloud-agents-profiles).
- **Session**: one conversation with a coding agent. Reuse its id to continue it. See [Sessions](/sandbox/sessions).
- **Template and snapshot**: a saved starting state and a saved copy of a sandbox's files. See [Snapshots and forks](/sandbox/snapshots).
- **Scoped token**: a short-lived token that lets a browser reach one sandbox without your account key. See [API keys and tokens](/sandbox/authentication).
- **Fleet**: several sandboxes under one budget and lifecycle. See [Fleets](/sandbox/agents-fleet).

## Choose a starting point

| You want | Start with |
|---|---|
| One command or an exact process | `box.exec()` |
| A coding agent on your own Claude, ChatGPT or coding plan | `backend.model.cliAuth`; see [Run a coding agent](/sandbox/cloud-agents) |
| One continuing agent conversation | `box.prompt()` with a `sessionId`, or `box.session(id)` |
| Several agents sharing one sandbox | `box.agents` |
| Separate machines or hard resource limits | A [fleet](/sandbox/agents-fleet) |
| A lead agent that hands work to workers in their own sandboxes | [Agent graphs](/sandbox/agents-graphs) |
| A browser view of a sandbox or session | A short-lived [scoped token](/sandbox/authentication) |

`box.agents` exists only after you import `@tangle-network/sandbox/agent`, which adds it to every sandbox handle:

```ts
import { Sandbox } from "@tangle-network/sandbox/agent";
```
