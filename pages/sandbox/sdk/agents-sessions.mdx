# Agents and sessions

Run an agent in a sandbox with access to its files and tools.
Choose a [supported harness](/infrastructure/harnesses), including Claude Code, Codex, OpenCode, or Pi.

## Choose an execution mode

| Mode                      | Use it for                                                                         | API                                                        |
| ------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Non-interactive           | Run a task and read its result.                                                    | `box.prompt()`                                             |
| Non-interactive, streamed | Show messages and tool activity while a task runs.                                 | `box.streamPrompt()`                                       |
| Interactive TUI           | Use the agent's native terminal interface, with keyboard input and screen updates. | [`session.interactive()`](/sandbox/sdk/interactive-agents) |
| Questions and approvals   | Let a headless agent ask a user for input in your application.                     | `backend.interactions`, `session.interactions()`           |

Streaming does not require a TUI.
Headless agents can also ask questions or request approvals when you enable those interactions.

## Enable questions and approvals

Enable the interaction kinds your application handles with `backend.interactions`.
This example lets Codex ask a question and prints requests while the agent runs.
Keep this stream open while another process or your application sends the answer.

<CodeDisplay language="typescript" code={agentModeExamples.questions} />

| Setting            | Agent behavior                      |
| ------------------ | ----------------------------------- |
| `question: true`   | Ask the user to answer or choose.   |
| `permission: true` | Request a tool or command approval. |
| `plan: true`       | Submit a plan for a decision.       |

Unsupported interaction kinds fail when the session initializes.
Read `interaction` events as they arrive.
`session.interactions()` retrieves outstanding requests when your application reconnects.

### Answer a question

Set `TANGLE_SESSION_ID` to the printed session ID.
Set `TANGLE_QUESTION_ID` to `event.data.request.id` from the question interaction.
Set `TANGLE_ANSWERS_JSON` using `request.answerSpec.fields` and your user's answers.
For a string-array field named `q0`, an answer could be `{"q0":["My project"]}`.

<CodeDisplay language="typescript" code={agentModeExamples.answer} />

Keep the acknowledgement and inspect the session before sending another turn.
Respond to permissions with `respondToPermission()` and plans with `approvePlan()` or `rejectPlan()`.
Plan decisions can enqueue a follow-up turn; do not submit that turn again.

## Reconnect to a durable turn

Use `dispatchPrompt()` when work must continue after the client disconnects.
Save the sandbox ID, session ID, and turn ID in your job record before dispatching.
Set the corresponding environment variables for this example.

<CodeDisplay language="typescript" code={sandboxCode.durableSessions} />

Reuse the same turn ID and prompt when retrying the same job.
A completed result is deduplicated while its cache is retained.
A session ID alone does not deduplicate completed turns.

Keep the receipt's `executionId` to reconnect to that specific execution.
`session.events({ executionId })` follows its output.
Delete the sandbox after the job and its retries finish.
