# Fleets

Manage several sandboxes as one workload.
Give workers stable names, send work to selected machines, and track their runtime and spending.

## Run agents with a budget

Choose each agent's harness and task.
Use `placement: "dedicated"` when agents need separate filesystems.

<CodeDisplay language="typescript" code={fleetGpuExamples.budgetedAgents} />

`budgetUsd` creates a budgeted Platform key for the fleet's compute and model usage.
Use `run()`, `runAll()`, or `prompt()` on the creating client to keep agent turns within that budget.
A refused model charge stops the run.
The outcome may be `failed` with HTTP `402`, including when an ancestor key's budget refuses authorization.
Inspect the returned error; a positive fleet balance does not guarantee authorization.

`policy.maxSpendUsd` alone checks the estimated creation cost.
Use `budgetUsd` for metered spending limits.

| Setting                                  | Use                                                          |
| ---------------------------------------- | ------------------------------------------------------------ |
| `agents[].harness`                       | Choose Claude Code, Codex, Pi, or another supported harness. |
| `agents[].model`                         | Select the model for that agent.                             |
| `agents[].profile`                       | Supply an inline agent profile or a saved `profileId`.       |
| `placement: "dedicated"`                 | Give each agent its own sandbox.                             |
| `placement: { agentsPerSandbox: 2 }`     | Run multiple sessions per sandbox with shared files.         |
| `runAll(message, { agents: ["tools"] })` | Send a turn to selected agents.                              |

The creating client holds the budgeted key.
A new client can inspect or delete the fleet, but cannot resume budgeted agent turns with that key.

## Inspect runtime and cost

Set `TANGLE_FLEET_ID` to an existing fleet.
These examples leave its workers running.

<CodeDisplay examples={[
  { language: "typescript", code: fleetGpuExamples.fleetUsage },
  { language: "python", code: fleetGpuExamples.fleetUsagePython },
]} />

`usage()` reports machine state and metered runtime when available.
`cost()` estimates compute charges; it is not an invoice or model-usage total.
For a budgeted fleet, `spend()` reports settled charges and remaining budget.
Use [trace analysis](/sandbox/sdk/traces) to inspect individual runs.

## Stop work and release workers

`cancel()` interrupts agent sessions and child fleets while keeping the machines.
`delete()` removes the fleet and its machines.

  { language: "typescript", code: fleetGpuExamples.deleteFleet },

To stop a single worker, obtain it with `await fleet.sandbox(machineId)` and call its lifecycle methods.
Use [batch tasks](/sandbox/sdk/parallel) when each job can finish in temporary sandboxes.
