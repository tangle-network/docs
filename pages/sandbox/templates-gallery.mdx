# Start from templates and custom images

Start sandboxes with your tools already installed: pick an environment, start from a public, team or personal template, publish your own, or bring a container image.

![The Templates page at sandbox.tangle.tools, Public tab, with the Universal starter environment and its Create sandbox button](/images/docs/templates-public.png)

The default image already carries Python 3.12 with numpy, pandas, matplotlib and scikit-learn, and Node 22 with pnpm and TypeScript. Reach for a template or an image when your coding agent needs more than that.

The list holds `universal`, the default, and each of your saved templates as `template:<id>`. `runtimes` says whether an environment can run under `docker`, `firecracker` or both. Pass an id as `environment` at create, or omit it for the default.

## Start from a public template

```ts
const [template] = await client.publicTemplates.list({ query: "python" });
if (!template) throw new Error("No matching public template");

const box = await client.create({ publicTemplateId: template.id });
try {
  console.log((await box.exec("ls")).stdout);
} finally {
  await box.delete();
}
```

`publicTemplates.list({ query, tag, featuredOnly, limit, offset })` searches the gallery, `featured()` returns the featured set, `get(idOrSlug)` returns one template, and `versions(idOrSlug)` lists its published versions. Explicit create fields win over what the template sets.

### Pin a version

Templates are versioned. Pin the version when you need every sandbox to start the same:

```ts
const [version] = await client.publicTemplates.versions(template.id);
const box = await client.create({
  publicTemplateId: template.id,
  publicTemplateVersionId: version.id,
});
```

```bash
tangle template list
tangle template get <slug>
tangle template versions <slug>
tangle sandbox create --public-template <slug> --public-template-version <version-id>
```

## Publish your own template

Set up a sandbox the way you want it, snapshot it, and publish the snapshot. Publication runs as a job: the SDK waits until the template is published and visible.

```ts
const box = await client.create({ name: "duckdb-agent-base" });
await box.exec("pip install duckdb polars");
const snap = await box.snapshot({ tags: ["duckdb"] });

const template = await client.publicTemplates.publish(
  {
    name: "DuckDB coding agent",
    snapshotId: snap.snapshotId,
    sourceSandboxId: box.id,
    description: "DuckDB and Polars for data coding agents",
    tags: ["duckdb", "python"],
  },
  { onProgress: (job) => console.log(job.id, job.status) },
);
console.log(template.id);
```

`name`, `snapshotId` and `sourceSandboxId` are required. `publishVersion(idOrSlug, { snapshotId, sourceSandboxId, releaseNotes })` adds a version to a template you own. `forkedFromTemplateId` records which template yours was built from; it copies nothing.

A publication that is interrupted, or a wait you stop with `signal`, throws `PublicTemplatePublishError` with the accepted `job`. The job may still be running. Continue it with the same input:

```ts
import { PublicTemplatePublishError } from "@tangle-network/sandbox";

try {
  await client.publicTemplates.publish(input);
} catch (error) {
  if (error instanceof PublicTemplatePublishError && error.job) {
    await client.publicTemplates.publish(input, { resumeJobId: error.job.id });
  } else {
    throw error;
  }
}
```

```bash
tangle template publish "DuckDB coding agent" <snapshot-id> <sandbox-id> --tags duckdb --json
tangle template publish "DuckDB coding agent" <snapshot-id> <sandbox-id> --resume-job <job-id> --json
tangle template publish-version <id-or-slug> <snapshot-id> <sandbox-id> --release-notes "Adds polars"
```

The CLI's `--timeout` on `template publish` is in seconds. Progress goes to stderr, and a JSON error keeps the accepted job id. A blocked or failed scan does not publish the template.

Over REST, the publish POST answers `202` with `{ job, artifact }`. Read `GET /v1/public-templates/publish-jobs/{jobId}` until the job finishes; an accepted request is not a published template.

## Share a template with your team

A team template is visible to everyone in the team.

```ts
const tmpl = await client.teams.createTemplate(teamId, {
  name: "checkout-service",
  snapshotId: snap.snapshotId,
  description: "Repo cloned, dependencies installed",
});
const box = await client.create({ templateId: tmpl.id, teamId });

console.log(await client.teams.listTemplates(teamId));
await client.teams.deleteTemplate(teamId, tmpl.id);
```

```bash
tangle team templates create checkout-service <snapshot-id> --description "Repo cloned"
tangle team templates list
tangle team templates delete <template-id>
```

Personal templates have no SDK or CLI command. Create them with `POST /v1/templates` (`name`, `snapshotId`, `sourceSandboxId`, optional `description`, `environment` and `config`), list with `GET /v1/templates`, and delete with `DELETE /v1/templates/{id}`. They appear in `environments.list()` as `template:<id>`.

## Bring a container image

`environment` also takes a container image reference:

```ts
const box = await client.create({ environment: "python:3.12-slim", runtime: "docker" });
```

Under `runtime: "firecracker"`, the image must be pinned as `repository@sha256:<digest>` and carried by the Firecracker hosts. `environments.list()` shows which runtimes each catalog image supports.

### Publish an image from a running sandbox

`box.images.publish` builds the sandbox's workspace with a Dockerfile and pushes it to your registry. The registry credentials go to the builder, never into the sandbox.

```ts
await box.write("Dockerfile", "FROM python:3.12-slim\nRUN pip install duckdb\n");
const image = await box.images.publish({
  repository: "ghcr.io/acme/agent-base",
  auth: { username: "acme-bot", password: process.env.GHCR_TOKEN! },
  platform: "linux/amd64",
});
console.log(image.image, image.digest);

const next = await client.create({ environment: image.image, runtime: "docker" });
```

`contextPath` and `dockerfilePath` default to `.` and `Dockerfile`. Where no builder is available, the call fails with `WORKSPACE_IMAGE_BUILDER_UNAVAILABLE` or `IN_BOX_DOCKER_UNAVAILABLE`. Image builds through `POST /v1/images` are not offered and answer `403 IMAGE_BUILDS_DISABLED`.

## Python and REST

Python lists environments and starts from templates with `template_id`, `public_template_id` and `public_template_version_id` on create. It has no public template, team template or image publishing methods. Call those routes with `client.fetch`, which returns the raw response and does not raise on an error status:

```python
templates = client.fetch("GET", "/v1/public-templates", params={"q": "python"}).json()["templates"]
client.fetch("POST", "/v1/templates", json={"name": "base", "snapshotId": snapshot_id, "sourceSandboxId": box.id})
```
