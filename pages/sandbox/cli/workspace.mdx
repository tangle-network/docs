# File, git, process and preview commands

Move files in and out of a sandbox, search its code, run git, start and watch long-running processes, share a port as a public link and run code in a kernel.

```bash
tangle fs upload my-box ./data.csv /home/agent/data.csv
tangle process spawn my-box "npm run dev"
tangle preview create my-box 3000
tangle fs download my-box /home/agent/report.txt ./report.txt
```

Every command here resumes a stopped sandbox first and waits up to 120 s for it.
`fs upload` and `fs download` move one file; to move a directory, use the TypeScript SDK's `uploadDirectory` or `fs.downloadDir`.

## Files

### `tangle fs upload`

Upload a file to a sandbox.

Uploads one local file to a sandbox path.

```bash
tangle fs upload <sandbox-id-or-name> <local-path> <remote-path>
```

Request: `POST {runtimeUrl}/fs/upload-session`

```bash
tangle fs upload my-box ./data.csv /home/agent/data.csv
```

- Uses an upload session: POST upload-session, PUT parts/`{n}`, POST commit.
- A missing local file fails before any upload.
- `--json` prints `{success, remotePath, size, ...}`.
- Resumes a stopped sandbox first and waits up to 120000 ms for it to run.

### `tangle fs download`

Download a file from a sandbox.

Downloads one sandbox file to a local path.

```bash
tangle fs download <sandbox-id-or-name> <remote-path> <local-path>
```

Request: `GET {runtimeUrl}/fs/download/{path}`

```bash
tangle fs download my-box /home/agent/report.txt ./report.txt
```

- `--json` prints `{success, remotePath, size, ...}`.
- Resumes a stopped sandbox first and waits up to 120000 ms for it to run.

### `tangle fs ls`

List directory contents.

Lists a directory (default '.'); `-l` adds mode, owner, group, size and date; `-a` includes hidden files.

```bash
tangle fs ls <sandbox-id-or-name> [path] [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `-l, --long` |  | Show detailed information |
| `-a, --all` |  | Include hidden files |

Request: `GET {runtimeUrl}/fs/list/{path}`

```bash
tangle fs ls my-box /
```

- `--json` prints the entry array.
- Resumes a stopped sandbox first and waits up to 120000 ms for it to run.

### `tangle fs stat`

Request: `GET {runtimeUrl}/fs/stat/{path}`

```bash

```

| Flag | Default | Description |
| --- | --- | --- |
| `-p, --parents` |  | Create parent directories as needed |

### `tangle fs exists`

Check if a path exists.

Prints 'exists' or 'not found'.

```bash
tangle fs exists <sandbox-id-or-name> <path>
```

Request: `GET {runtimeUrl}/fs/exists/{path}`

```bash
tangle fs exists my-box /home/agent/present
```

- Exits 1 when the path is missing, but with `--json` it prints `{path, exists:false}` and exits 0.
- Resumes a stopped sandbox first and waits up to 120000 ms for it to run.

## Search

### `tangle search`

Search for text patterns in sandbox files (ripgrep).

Searches sandbox files with ripgrep and prints path:line:column: text per match.

```bash
tangle search <id-or-name> <pattern> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `-g, --glob <pattern>` |  | File glob filter (e.g. '**/*.ts') |
| `-n, --max-results <count>` |  | Max results to return |
| `-i, --ignore-case` |  | Case-insensitive search |

Request: `POST {runtimeUrl}/search`

```bash
tangle search my-box TODO
```

- `--json` prints one JSON match per line (NDJSON).
- Does not resume a stopped sandbox, unlike fs and exec.

## Processes

### `tangle process spawn`

Spawn a process without blocking (returns PID).

Starts a command in the background and prints its PID; `--blocking` waits like `tangle exec`.

```bash
tangle process spawn <id-or-name> <command> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--cwd <dir>` |  | Working directory |
| `--env <vars...>` |  | Environment variables (KEY=VALUE) |
| `-t, --timeout <ms>` |  | Timeout in milliseconds |
| `--blocking` |  | Wait for completion (default: false) |

Request: `POST /v1/sandboxes/{id}/runtime/process/spawn`

- `--json` prints `{pid, command}`; with `--blocking` it prints the exec result.
- `<command>` is a single argument; quote it.
- Resumes a stopped sandbox first and waits up to 120000 ms for it to run.

### `tangle process list`

List all processes in a sandbox.

Lists processes with PID, command, status, exit code and start time.

```bash
tangle process list <id-or-name> [options]
```

Aliases: `ls`

| Flag | Default | Description |
| --- | --- | --- |
| `--running` |  | Show only running processes |

Request: `GET {runtimeUrl}/process`

```bash
tangle process list my-box
```

- Alias: ls.
- `--running` shows only running processes.
- Resumes a stopped sandbox first and waits up to 120000 ms for it to run.

### `tangle process get`

Get detailed info about a process.

Shows one process's command, working directory, status, exit code and times.

```bash
tangle process get <id-or-name> <pid>
```

Request: `GET {runtimeUrl}/process/{pid}`

- Exits 1 with 'Process `<pid>` not found' when missing.
- Resumes a stopped sandbox first and waits up to 120000 ms for it to run.

### `tangle process kill`

Kill a process.

Sends a signal (default SIGTERM) to a process, or its whole tree with `--tree`.

```bash
tangle process kill <id-or-name> <pid> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `-s, --signal <signal>` | `SIGTERM` | Signal to send (SIGTERM, SIGKILL, etc.) |
| `--tree` |  | Also kill descendants of the tracked process |

Request: `DELETE {runtimeUrl}/process/{pid}`

- `--json` prints `{pid, signal, tree?, killed:true}`.
- Resumes a stopped sandbox first and waits up to 120000 ms for it to run.

### `tangle process logs`

Stream buffered and live process logs until the process exits.

Prints buffered and live logs of a process until it exits.

```bash
tangle process logs <id-or-name> <pid> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--stdout-only` |  | Only show stdout |
| `--stderr-only` |  | Only show stderr |

Request: `GET {runtimeUrl}/process/{pid}/logs`

- Remote stdout goes to local stdout and remote stderr to local stderr.
- `--json` prints one JSON log entry per line (NDJSON), not one document.
- Resumes a stopped sandbox first and waits up to 120000 ms for it to run.

## Run code

### `tangle run`

Run code in a persistent kernel inside a sandbox. Variables persist across calls in the same `--session`.

Runs a source file, or stdin with '-', in a persistent language kernel (python, node, typescript, bash) inside a sandbox; variables persist across calls that share `--session`.

```bash
tangle run <id-or-name> [file] [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `-l, --lang <lang>` |  | Force language: python \| node \| typescript \| bash. Required for stdin. |
| `-s, --session <id>` |  | Session id for kernel scoping |
| `-t, --timeout <ms>` | `60000` | Per-call timeout in ms (0 disables) |
| `--save-images <dir>` |  | Write image results into this directory (default: $TMPDIR/tangle-run-images/`<sandbox>`/). |
| `--no-save-images` |  | Don't write image results to disk; print summary only |

Request: `POST /v1/sandboxes/{id}/runtime/code/exec`

- Language comes from the file extension (.py, .js/.mjs/.cjs, .ts/.tsx, .sh/.bash) or `--lang`; stdin requires `--lang`.
- Image results are written to $TMPDIR/tangle-run-images/`<sandbox>`/ unless `--save-images <dir>` or `--no-save-images`; dataframes, JSON, HTML and errors are summarized on stderr.
- `--timeout` defaults to 60000 ms; 0 disables it.
- Exits with the kernel's exit code; `--json` prints the result document.
- Resumes a stopped sandbox first and waits up to 120000 ms for it to run.
