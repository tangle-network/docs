# Hub and line commands

Hub holds your connections to outside accounts, such as GitHub, and runs their tools with your approval rules. Lines give an agent a phone number or mailbox.

```bash
tangle hub connect github
tangle hub tools search "create issue"
tangle agent prompt my-box "Triage new issues" --connection github:github.issues.create
tangle lines list
```

`tangle hub exec` runs a Hub tool, not a shell command; `tangle exec` runs a shell command in a sandbox.
Hub and lines live on Tangle Platform, so `--base-url` on these commands points at the Platform host.

## Hub

### `tangle hub status`

Show Hub auth and connection status.

Shows Hub authentication and connection status.

```bash
tangle hub status
```

Request: `GET /v1/hub/status`

```bash
tangle hub status
```

### `tangle hub connect`

Connect a provider account.

Starts OAuth for a provider, opens the authorization URL in a browser (or prints it with `--no-browser`) and exits.

```bash
tangle hub connect <provider> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--no-browser` |  | Print the authorization URL instead of opening it |
| `--parameter <key=value>` |  | Provider-specific OAuth value. Repeatable. |

Request: `POST /v1/hub/connections/{provider}/start`

```bash
tangle hub connect github
```

- With no credential on a terminal it runs browser login first.
- It does not wait for authorization; check with `tangle hub status`.
- `--json` prints the start response with the OAuth state removed.

### `tangle hub call`

Execute a Hub tool.

Executes a Hub tool: path tokens followed by a JSON input argument.

```bash
tangle hub call <args...> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--connection <ref>` |  | Hub connection id, or provider[:account] |
| `--auto-approve` |  | Approve a HUB_APPROVAL_REQUIRED execution and retry once |
| `--approve` |  | Alias for `--auto-approve` |
| `--no-hub-key` |  | Do not auto-mint a platform Hub key; use the stored credential as-is |

Request: `POST /v1/hub/exec`

- Always prints the tool result as JSON.
- `--approve`/`--auto-approve` approves a HUB_APPROVAL_REQUIRED execution and retries once.

### `tangle hub exec`

Execute a Hub tool.

Same as `tangle hub call`; runs a Hub tool, not a sandbox command.

```bash
tangle hub exec <args...> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--connection <ref>` |  | Hub connection id, or provider[:account] |
| `--auto-approve` |  | Approve a HUB_APPROVAL_REQUIRED execution and retry once |
| `--approve` |  | Alias for `--auto-approve` |
| `--no-hub-key` |  | Do not auto-mint a platform Hub key; use the stored credential as-is |

Request: `POST /v1/hub/exec`

- Not the same as `tangle exec`, which runs a shell command in a sandbox.

### `tangle hub resume`

Resolve a Hub approval created by a paused execution.

Accepts or declines the approval a paused execution created; it does not rerun the execution.

```bash
tangle hub resume <approval-id> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--accept` |  | Approve the execution approval |
| `--decline` |  | Deny the execution approval |
| `--cancel` |  | Unsupported for approval-backed Hub resume |

Request: `POST /v1/hub/approvals/{approvalId}/approve`

```bash
tangle hub resume appr_123
```

- `--decline` posts .../deny; `--cancel` is accepted but unsupported.

### `tangle hub permissions set`

Set Hub permission for one action.

Sets allow, ask or deny for one action on a connection.

```bash
tangle hub permissions set [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--connection <ref>` |  | Hub connection id, or provider[:account]. Required. |
| `--action <path>` |  | Executor action path. Required. |
| `--decision <allow\|ask\|deny>` |  | Permission decision. Required. |

Request: `PUT /v1/hub/policies`

```bash
tangle hub permissions set --connection hubconn_github_abc123 --action github.issues.create --decision ask
```

### `tangle hub permissions revert-writes`

Revoke a bulk `--allow-writes` grant for a connection (deletes only the auto-granted write rows; manual permissions are untouched).

Removes the write grants that `--allow-writes` added for a connection; manual permissions stay.

```bash
tangle hub permissions revert-writes [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--connection <ref>` |  | Hub connection id, or provider[:account]. Required. |

Request: `POST /v1/hub/policies/revert-writes`

```bash
tangle hub permissions revert-writes --connection hubconn_github_abc123
```

### `tangle lines connect`

Bind an owned number or identity through Hub; no provider rental is purchased.

```bash
tangle lines connect <connection-id> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--transport <transport>` | `imessage` | imessage, whatsapp, sms, email, voice, or telegram |
| `--number-id <id>` |  | Exact owned provider number ID; required for voice, SMS, WhatsApp and Linq iMessage |
| `--address <email>` |  | Owned mailbox on a verified email domain |
| `--reference <reference>` |  | Stable client reference; keep it unchanged on retry. Required. |
| `--label <label>` |  | Line display name |
| `--yes` |  | Authorize provider webhook configuration and line binding |

Request: `POST /v1/lines`

```bash
tangle lines connect conn_p --transport voice --number-id pn_voice --reference support --yes --json
```

- `--yes` authorizes provider webhook configuration and line binding.

### `tangle lines attach`

Attach a saved agent to any sandbox, or use an isolated on-demand member instance.

Attaches a saved agent profile to a line, on an existing sandbox or an isolated on-demand instance.

```bash
tangle lines attach <line-id> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--file <path>` |  | Reviewed native attachment JSON (exclusive with quick-setup flags) |
| `--profile-id <id>` |  | Owner-scoped saved profile; each turn pins its source revision |
| `--member <address>` |  | The one allowed sender: E.164 phone or email |
| `--sandbox <id>` |  | Use an existing sandbox instead of an on-demand instance |
| `--instance-prefix <prefix>` |  | Stable instance namespace; defaults to profile:`<profile-id>`: |
| `--tools <mode>` |  | chat denies tools; act applies the profile's tools and permissions |
| `--turns-per-day <count>` |  | Per-member daily turn ceiling (default 30) |
| `--yes` |  | Authorize agent execution and spend against your key limits |

## Context inside a line sandbox

### `tangle context`

Show live line identity, members, consent, reminders and quotas.

```bash
tangle context
```

- Inside a line box it authenticates with TANGLE_LINE_TOKEN (lrc_ prefix) and TANGLE_HUB_URL; elsewhere it uses the platform credential.
- Always prints JSON.
