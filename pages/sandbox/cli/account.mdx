# Account, key, secret, team and template commands

Log in, manage profiles, mint and revoke API keys, store secrets, run a team and publish templates.

```bash
tangle auth login
tangle keys create ci-agents --budget-usd 25 --expires-in-days 30
printf %s "$OPENAI_API_KEY" | tangle secret create OPENAI_API_KEY --value-stdin
tangle team switch Acme
```

`keys create` and `keys revoke` need an API-key login (`tangle auth login --api-key ...` or `TANGLE_API_KEY`). A browser login cannot create or revoke keys.
`keys` talks to Tangle Platform; `--platform-url` names that host and `--base-url` still names the Sandbox API.

## Log in and profiles

### `tangle auth login`

Authenticate with browser login, device code, or an API key.

Authenticates and stores a credential for a profile. Default: browser login through a 127.0.0.1 loopback callback; `--no-browser`: device code; global `--api-key`: validates the key against GET /v1/account/me and stores it.

```bash
tangle auth login [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--no-browser` |  | Use device-code login instead of opening a browser |
| `--profile <name>` |  | Profile name |
| `--provider <provider>` |  | Identity provider (github, google, microsoft) |
| `--app <app>` | `sandbox` | Product to authorize (sandbox or solve) |

Request: `POST /auth/cli/exchange`

```bash
tangle auth login
```

- Browser flow: opens `<base-url>/auth/cli/login?callback_url=http://127.0.0.1:<port>/callback?state=<nonce>`, waits up to 2 minutes, then POST /auth/cli/exchange.
- Device flow: POST /auth/cli/device/start, then polls POST /auth/cli/device/poll at the server interval (default 5 s) for up to 15 minutes.
- `--app` solve always uses the device flow against the fixed platform host and also opens the prefilled URL unless `--no-browser`.
- API keys must start with sk_ or sk-tan-; anything else exits 1 before any request.
- Before any interactive login it proves the credential store can write, read and delete a probe value; without an OS keychain it uses ~/.tangle/credentials.json (mode 0600).
- A sandbox login makes the profile active; a solve login does not.
- No JSON document is printed; success lines go to stdout (stderr under `--json`).

### `tangle auth logout`

Remove stored credentials.

Removes the profile's stored credential from the OS keychain and the credentials file, keeping its base URL and team settings.

```bash
tangle auth logout [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--profile <name>` |  | Profile name |
| `--app <app>` | `sandbox` | Product credentials to remove (sandbox or solve) |

```bash
tangle auth logout
```

- Local only; no network request.

### `tangle auth status`

Show current authentication status.

Checks the stored or supplied credential against the sandbox API and probes the platform control plane with the same profile.

```bash
tangle auth status [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--profile <name>` |  | Profile name |
| `--app <app>` | `sandbox` | Product credentials to check (sandbox or solve) |

Request: `GET /v1/account/me`

```bash
tangle auth status
```

- `--json` prints `{authenticated, profile, baseUrl, credentialSource, account, sandbox, platform}`; missing credentials print `{authenticated:false, reason:'missing_credentials'}` and exit 0.
- Exits 1 when the sandbox API or the platform refuses the credential; an unreachable platform still exits 0 and sets platform.reachable=false.
- credentialSource is one of flag, env, keychain, file.

## API keys

### `tangle keys list`

List your active API keys.

Lists your active platform API keys.

```bash
tangle keys list [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--platform-url <url>` |  | Override the platform URL (id.tangle.tools) |

Request: `GET /v1/keys`

```bash
tangle keys list
```

- Works from a browser login: the CLI exchanges the stored session for a short-lived platform key.
- `--platform-url` names the platform host; the global `--base-url` names the sandbox host the session is exchanged at.

### `tangle keys create`

Create a new API key.

Creates a platform API key with optional product, budget, rate and expiry limits and prints the key once.

```bash
tangle keys create <name> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--product <product>` |  | Restrict the key to one product (router\|sandbox\|blueprint-agent\|evals\|agent-builder). Omit for all products. |
| `--budget-usd <amount>` |  | Hard budget cap in USD |
| `--rpm-limit <limit>` |  | Requests-per-minute cap |
| `--expires-in-days <days>` |  | Expire the key after N days (integer) |
| `--platform-url <url>` |  | Override the platform URL (id.tangle.tools) |

Request: `POST /v1/keys`

```bash
tangle keys create ci-agents --budget-usd 25
```

- Refused before any request when the credential was minted from a browser login; set TANGLE_API_KEY or log in with `--api-key`.

### `tangle keys revoke`

Revoke an API key.

Revokes a platform API key after confirmation.

```bash
tangle keys revoke <keyId> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--yes` |  | Skip the confirmation prompt |
| `--platform-url <url>` |  | Override the platform URL (id.tangle.tools) |

Request: `DELETE /v1/keys/{keyId}`

```bash
tangle keys revoke key_1
```

- Confirmation is skipped with `--yes` (not `--force`).
- Same minted-credential refusal as keys create.

## Secrets

### `tangle secret create`

Create a new secret.

Creates an account secret; the value comes from the argument, from stdin with `--value-stdin`, or from a hidden prompt.

```bash
tangle secret create <name> [value] [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--value-stdin` |  | Read secret value from stdin |

Request: `POST /v1/secrets`

```bash
tangle secret create API_KEY
```

- With neither a value nor `--value-stdin` it prompts on stderr with echo off: "Enter value for secret '`<name>`': ".
- A value argument and `--value-stdin` together are refused; an empty value is refused.
- Select the secret for a sandbox with `tangle sandbox create --secret <name>`.

### `tangle secret list`

List all secrets.

Lists secret names with created and updated times; values are never printed.

```bash
tangle secret list
```

Request: `GET /v1/secrets`

```bash
tangle secret list
```

### `tangle secret delete`

Delete a secret.

Deletes a secret after a y/N confirmation.

```bash
tangle secret delete <name> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--force` |  | Skip confirmation prompt |

Request: `DELETE /v1/secrets/{name}`

```bash
tangle secret delete API_KEY
```

- `--force` skips the prompt; `--json` prints `{success:true, deleted:<name>}`.

### `tangle template publish`

Publishes a snapshot of a sandbox as a new public template and waits for the publication job.

```bash
tangle template publish <name> <snapshot-id> <sandbox-id> [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--timeout <seconds>` |  | Maximum wait for publication |
| `--resume-job <id>` |  | Resume an accepted publication for this snapshot |
| `--slug <slug>` |  | Stable public slug |
| `-d, --description <description>` |  | Template description |
| `--readme <markdown>` |  | README markdown |
| `--tags <tags...>` |  | Template tags |
| `--release-notes <text>` |  | Release notes |
| `--team-id <id>` |  | Publish under a team |
| `--forked-from <id>` |  | Fork source template id |

Request: `POST /v1/public-templates`

```bash
tangle template publish <name> <snapshot-id> <sandbox-id>
```

- `--timeout` is in SECONDS here.
- Progress lines 'Publication `<job>`: `<status>`' go to stderr; Ctrl-C stops waiting, and an interrupted or timed-out job prints the exact `--resume-job <id>` command to continue.

### `tangle template publish-version`


| Flag | Default | Description |
| --- | --- | --- |
| `--timeout <seconds>` |  | Maximum wait for publication |
| `--resume-job <id>` |  | Resume an accepted publication for this snapshot |
| `--readme <markdown>` |  | README markdown |
| `--tags <tags...>` |  | Template tags |
| `--release-notes <text>` |  | Release notes |

Request: `POST /v1/public-templates/{idOrSlug}/versions`

```bash

```

- `--timeout` is in seconds; same resume behavior as template publish.
