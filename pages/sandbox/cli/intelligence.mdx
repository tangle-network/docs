# Intelligence, trace and Solve commands

Read intelligence reports for sandboxes and fleets, list and fetch traces, send a local coding agent's telemetry to Tangle Intelligence, and enter Solve competitions.

```bash
tangle intelligence sandbox my-box
tangle traces list
tangle connect claude-code --verify
```

`tangle connect` changes files on your machine. `connect codex` rewrites `~/.codex/config.toml` without asking (pass `--no-write` to only print).
`connect claude-code` offers to append a block to `~/.zshrc` or `~/.bashrc`, and writes `~/.zshrc` when your shell is neither zsh nor bash.
`connect --verify` waits in seconds, polling every 3 s, and exits 1 when nothing arrives before `--timeout` (default 120 s).

`tangle traces` reads the Intelligence API, so `--base-url` on it points at that host; `TANGLE_INTELLIGENCE_BASE_URL` sets it for every call.

## Intelligence reports

### `tangle intelligence connect`

Connect local agent CLIs to Tangle Intelligence.

Installs native hook files for local agent CLIs in a workspace so they emit traces to Tangle Intelligence, then sends a smoke trace.

```bash
tangle intelligence connect [agent] [options]
```

Aliases: `connect-agent`

| Flag | Default | Description |
| --- | --- | --- |
| `--endpoint <url>` | `https://intelligence.tangle.tools/v1/otlp` | OTLP endpoint base |
| `--workspace <path>` | `.` | Workspace to write hook files into |
| `--service-name <name>` |  | OTel service.name label |
| `--environment <name>` | `local` | OTel deployment.environment label |
| `--dry-run` |  | Print planned writes without changing files |
| `--hook-command <command>` | `tangle intelligence hook` | Command native hooks should run |
| `--no-smoke` |  | Skip the install smoke trace |

```bash
tangle intelligence connect codex --workspace ~/repo --no-smoke
```

- `--dry-run` prints the planned writes; `--no-smoke` skips the smoke trace.

### `tangle intelligence hook`

Emit one local agent hook event to Tangle Intelligence.

Emits one local agent hook event as OTLP; native agent hooks call it.

```bash

```

| Flag | Default | Description |
| --- | --- | --- |
| `--agent <agent>` |  | Agent name. Required. |
| `--event <event>` |  | Hook event name. Required. |
| `--payload <json>` |  | Hook payload JSON |
| `--endpoint <url>` |  | OTLP endpoint base |
| `--service-name <name>` |  | OTel service.name label |
| `--environment <name>` |  | OTel deployment.environment label |
| `--session-id <id>` |  | Session id override |
| `--dry-run` |  | Build the OTLP request without sending it |
| `--non-blocking` |  | Do not fail the parent agent process |

- Reads the hook payload from piped stdin (max 65536 bytes) when `--payload` is absent.

## Traces and runs

### `tangle traces list`

List trace summaries (one row per trace), newest first.

Lists trace summaries, newest first, with filters.

```bash
tangle traces list [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--from <iso>` |  | ISO-8601 lower bound on received time (inclusive) |
| `--to <iso>` |  | ISO-8601 upper bound on received time (inclusive) |
| `--model <model>` |  | Exact model match (any span carried this model) |
| `--run <runId>` |  | Exact run id match |
| `--status <status>` |  | ERROR \| OK |
| `-q, --query <text>` |  | Substring over span name |
| `--cursor <cursor>` |  | Opaque pagination cursor from a prior page |

## Telemetry from a local coding agent

### `tangle connect`

Connect a local coding agent's telemetry to Tangle Intelligence, content on (for SDK integration snippets, see 'tangle agent connect').

Configures a local coding agent (claude-code, codex, opencode, openclaw, hermes, nanoclaw) to send telemetry with content to Tangle Intelligence; `--verify` checks that content arrives.

```bash
tangle connect [agent] [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--endpoint <url>` | `https://intelligence.tangle.tools/v1/otlp` | OTLP endpoint base |
| `-p, --project <key>` |  | Project label (tangle.subject.key) to group runs; omit to set it yourself |
| `--rc <path>` |  | Shell rc file to append the Claude Code env block to |
| `--no-write` |  | Print the config instead of writing files (Claude Code / Codex) |
| `--inline-key` |  | Embed the resolved API key literally in the config (default: keep $`{TANGLE_API_KEY}`) |
| `--verify` |  | Poll onboarding status and report whether CONTENT is flowing |
| `--timeout <seconds>` | `120` | Verify poll timeout in seconds |
| `--run` |  | OpenCode only: run the content exporter against a live OpenCode server until interrupted |
| `--opencode-url <url>` |  | OpenCode server base URL for `--run` (or set OPENCODE_BASE_URL) |
| `--format <kind>` | `shell` | Claude Code output: shell (export block) \| env (.env / docker `--env-file`) \| dockerfile (ENV lines). env/dockerfile are the cron/container path, printed to stdout, no shell-rc edit, no TTY |
| `--content <tier>` | `full` | Claude Code content tier: full (everything) \| prompts (task+prompts+tool-args) \| metadata (telemetry on, content off) |

- This is Intelligence telemetry setup, not sandbox access; `tangle agent connect` prints SDK snippets.
- codex: merges an [otel] block into ~/.codex/config.toml immediately, without a prompt, unless `--no-write`.
- claude-code: prints an env block; on a terminal asks before appending it to the shell rc; `--format` env|dockerfile only prints.
- `--verify` polls every 3 s up to `--timeout` SECONDS (default 120) and exits 1 unless content was seen.

### `tangle opencode-exporter`

Export a running OpenCode's content to Tangle Intelligence (standalone shim).

Runs until Ctrl-C, forwarding a running OpenCode server's events with content to Tangle Intelligence.

```bash
tangle opencode-exporter [options]
```

| Flag | Default | Description |
| --- | --- | --- |
| `--endpoint <url>` | `https://intelligence.tangle.tools/v1/otlp` | OTLP endpoint base |
| `--opencode-url <url>` |  | OpenCode server base URL (or set OPENCODE_BASE_URL) |

- Same as `tangle connect opencode --run`.
- OPENCODE_BASE_URL or `--opencode-url` names the OpenCode server.
