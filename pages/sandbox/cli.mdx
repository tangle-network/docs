# tangle CLI

`tangle` creates sandboxes, runs commands and coding agents in them, and moves files, snapshots and previews from your terminal.
Every command prints JSON with `--json`, so the same commands work in scripts and CI.

## Install

The installer brings its own Node.js runtime, so it needs no Node, npm or sudo:

```bash
curl -fsSL https://sandbox.tangle.tools/install.sh | sh
export PATH="$HOME/.local/share/tangle-cli/bin:$PATH"
tangle --version
```

With Node.js 22.19 or newer, `npm install -g @tangle-network/sandbox-cli` installs the same CLI.

To run it once without installing, use `npx @tangle-network/sandbox-cli` or `npx tangle-sandbox`.

<Callout type="warning">
Never run bare `npx tangle`. That npm name belongs to an unrelated package.
</Callout>

## Log in

```bash
tangle auth login
tangle auth status
```

`tangle auth login` opens your browser and waits up to 2 minutes for you to sign in.
On a machine without a browser, `tangle auth login --no-browser` prints a URL and a device code; finish on any device within 15 minutes.
To use an API key instead, run `tangle auth login --api-key sk-tan-...`, or skip login and set `TANGLE_API_KEY`.

Login stores the credential in your OS keychain: the macOS keychain, or `secret-tool` on Linux.
On a Linux server or container with no keychain, login writes `~/.tangle/credentials.json` (mode 0600) instead; `TANGLE_API_KEY` or `TANGLE_API_KEY_FILE` skip the login.

Each command picks its credential in this order:

1. `--api-key` on the command line
2. `TANGLE_API_KEY_FILE`, a file holding an `sk-tan-` key, read on every use
3. `TANGLE_API_KEY`
4. the OS keychain entry for the active profile
5. `~/.tangle/credentials.json`, only when plaintext credentials are allowed

The CLI loads a `.env` file from the current directory when it starts, so a `TANGLE_API_KEY` or `TANGLE_BASE_URL` in that file applies to every command you run there.

[API keys and tokens](/sandbox/authentication) covers key scopes, budgets and expiry.

## Profiles and the config file

`~/.tangle/config.json` holds the active profile, each profile's API host and active team, the active sandbox and the default request timeout. Credentials are never stored in it.

Profiles let one machine hold several accounts:

```bash
tangle auth login --profile work
tangle auth profiles list
tangle auth profiles use work
TANGLE_PROFILE=work tangle sandbox list
```

There is no global `--profile` flag. Set `TANGLE_PROFILE` to pick a profile for one command.

`--profile` means a different thing on different commands:

| Command | `--profile` means |
| --- | --- |
| `tangle auth`, `tangle team`, `tangle solve` | the credential profile to use |
| `tangle agent prompt` | an agent profile to run: a JSON path, an https URL or `github:owner/repo/path@ref` |
| `tangle sandbox create` | an agent profile file or a saved profile name to install in the sandbox |
| `tangle sandbox get` | an on/off switch that prints the sandbox's agent profile provenance |

## The active sandbox

`tangle use <id-or-name>` saves a default sandbox. `--box <id>` and `TANGLE_SANDBOX` override it.
The default applies only to the one-argument form of `tangle agent prompt`; every other command takes the sandbox id or name.

```bash
tangle use my-box
tangle agent prompt "Summarize the README"
tangle exec my-box -- ls
```

## Global options

These work before or after any command.

| Option | What it does |
| --- | --- |
| `--json` | Print one JSON document on stdout, including errors. Spinners stop and status lines move to stderr. |
| `--api-key <key>` | Use this key for one command. |
| `--base-url <url>` | Send this command to another host. |
| `-V, --version` | Print the CLI version. |

`--base-url` names a different service for each command family: the Sandbox API for sandbox, exec, file and agent commands, Tangle Platform for `workflows`, `hub` and `lines`, and the Intelligence API for `traces`.
`tangle keys` takes `--platform-url` for the Platform host.

### Run a coding agent

```bash
tangle sandbox create --name fixer --git-url https://github.com/tangle-network/sandbox-demo
tangle agent prompt fixer "The test tagged null-guard fails. Fix the cause." --stream
tangle exec fixer -- npm test
tangle sandbox delete fixer --force
```

`sandbox create` waits up to 120 s for the sandbox to run. A stopped sandbox resumes on its own before `exec`, `ssh`, `fs`, `git`, `process`, `run` and `agent prompt`, which wait up to 120 s for it.

### Open a shell

`tangle ssh` works on a sandbox created with `--ssh`, `--ssh-key`, `--ssh-keys` or `--ssh-key-file`.
`--ssh` alone uploads the first of `~/.ssh/id_ed25519.pub`, `id_ecdsa.pub` or `id_rsa.pub`, and fails if none exists.
The connection runs over a WebSocket through the Sandbox API, so the sandbox opens no inbound port. The CLI does not check the sandbox's SSH host key.

```bash
tangle sandbox create --name dev --ssh
tangle ssh dev
tangle ssh dev -- uname -a
```

## Scripts and CI

### Output

With `--json`, stdout carries only the JSON document. These commands print one JSON object per line instead: `search --json`, `process logs --json` and `traces get --ndjson`.

These commands always print text, even with `--json`: `auth login`, `auth logout`, `sandbox delete`, `backend restart`, `ssh-keys delete`, `ssh`, `ssh-proxy`, `agent connect` and `mcp serve`.

An error under `--json` prints this envelope on stdout:

```json
{
  "ok": false,
  "error": {
    "code": "UNAUTHORIZED",
    "what": "...",
    "cause": "...",
    "nextStep": "...",
    "fix": { "command": "tangle auth login" },
    "retryable": false,
    "requestId": "...",
    "status": 401
  }
}
```

Without `--json`, an error prints one line on stderr with the cause, the next step and the command that fixes it. [Errors](/sandbox/errors) lists every code.

### Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Success |
| 1 | Failure. Also: `fs exists` found nothing (without `--json`), a fleet or batch member failed, a coding agent stopped to wait for an approval or an answer |
| 2 | `agent connect` got an unknown framework |
| 64 | Usage error: unknown command or option, missing graph parameter, unknown Hub provider |
| 65 | Invalid input: graph, agent profile (`PROFILE_INVALID`), workflow file or Hub tool |
| 69 | A dependency is unavailable: coding agent not installed, MCP server or network unreachable |
| 75 | Temporary: rate limited or at a limit; retry later |
| 77 | Log in again: expired or wrong credential, any HTTP 401, Hub not connected or approval needed |
| 78 | Configuration: subscription required, model not found, MCP blocked |
| 130 | Stopped with Ctrl-C (graph run, batch, interactive session) |
| 143 | An interactive session ended by SIGTERM |

`exec`, `run`, `sandbox gpu run` and `process spawn --blocking` exit with the remote command's exit code. `ssh` exits with ssh's exit code.

### Confirmations

Destructive commands ask y/N on stderr. In CI there is no answer, so pass the skip flag or the command fails with `Pass <flag> to skip the confirmation`.

| Command | Skip flag |
| --- | --- |
| `sandbox delete` | `--force` (`--json` does not skip it) |
| `secret delete`, `team transfer`, `team secret delete`, `team templates delete`, `hub connections revoke`, `workflows delete` | `--force` |
| `team leave` | `--force` or `--json` |
| `keys revoke`, `solve device revoke`, `lines connect` | `--yes` |

### Timeouts and remote arguments

Most `--timeout` flags are milliseconds: `exec` defaults to 60000, `agent prompt` to 300000 and `sandbox resume` to 120000. `template publish` and `connect --verify` take seconds.
On `sandbox create`, `--timeout` is the HTTP timeout. The sandbox's own limits are `--lifetime` (default 3600 s) and `--idle-timeout` (default 900 s); when either runs out the sandbox stops and is not deleted.

`exec`, `ssh` and `sandbox gpu run` pass unknown options to the remote side. Put `--` before the remote command so flags such as `-t` are not read as `tangle` options.
One argument after `--` runs as a shell script; several arguments are quoted one by one.

```bash
tangle exec my-box -- "npm ci && npm test"
tangle exec my-box -- ls -la /home/agent
```

### Things that surprise scripts

- `sandbox create` always waits for the sandbox to run; there is no `--no-wait`.
- `--secret` takes bare secret names. To keep a value out of the sandbox, use `--proxy-secret`; see [Secrets](/sandbox/secrets).
- `--accelerator-memory` is in decimal GB.
- `keys create` and `keys revoke` need an API-key login. A browser login gets a short-lived Platform key that cannot create or revoke keys.
- `snapshot restore` creates a new sandbox and takes a sandbox id, not a name. `snapshot revert` rolls the same sandbox back.
- `preview list` cuts ids to 12 characters; use `--json` for the full id `preview remove` needs.
- `tangle hub exec` runs a Hub tool. `tangle exec` runs a shell command in a sandbox.
- `tangle connect` sets up telemetry for a coding agent on your machine; `tangle agent connect` prints SDK snippets. Neither connects to a sandbox.

## A skill file for coding agents

The CLI ships a `SKILL.md` that teaches a coding agent the commands. Print its path and point your agent at it:

```bash
tangle skill path
```

## Things the CLI does elsewhere

- GPUs: `tangle sandbox gpu` attaches a GPU to a sandbox for one command or a session. See [GPU leases](/sandbox/gpu-leases).
- Workflows: `tangle workflows` drives workflows on Tangle Platform. See [Workflows](/sandbox/workflows) and [Workflow commands](/sandbox/cli/workflows).
- Secrets: `tangle secret` stores values, and `--secret` or `--proxy-secret` deliver them. See [Secrets](/sandbox/secrets).
- Network rules: the CLI shows a sandbox's network with `tangle sandbox network`; change egress rules from the SDK or the API. See [Network egress rules](/sandbox/egress).
