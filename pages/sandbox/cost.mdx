# Pricing and spend controls

A running sandbox is billed per second from your account's credit.
This page lists what you pay for, where to read the current rates, how to see what you have spent, and the settings that stop sandboxes and cap spend.

Current prices are on the [pricing page](https://sandbox.tangle.tools/pricing).

## What you pay for

| Charge | When it is billed | Where to read the rate |
|---|---|---|
| Compute | Per second while a sandbox runs, for its vCPUs, memory and disk, with an hourly minimum. Billing stops when the compute stops. | `GET /v1/pricing/sandboxes` |
| Egress | Outbound bytes beyond your plan's monthly allowance, counted per account per UTC calendar month. Inbound traffic is free. | `GET /v1/pricing/egress` |
| Model use | Only when the coding agent calls models through the Tangle Router. On your own key or subscription, your provider bills you instead. | [Tangle Router](https://router.tangle.tools) |
| GPU leases | While a lease is attached, up to the spend limit you set on it. | [GPU leases](/sandbox/gpu-leases) |

Both pricing routes are public and need no API key:

```bash
curl -s https://sandbox.tangle.tools/v1/pricing/sandboxes
curl -s https://sandbox.tangle.tools/v1/pricing/egress
```

The sandbox rate card gives USD per vCPU-hour, per GB-hour of memory and per GB-hour of disk, and the hourly minimum. A sandbox costs `vCPUs × cpuCoreHourUsd + memoryGB × memoryGBHourUsd + diskGB × diskGBHourUsd` per hour, and never less than `minChargeHourUsd`.

The egress terms list each plan's `includedBytes` and whether overage is `billed` at `usdPerGb` per 10^9 bytes or `refused`.
On a plan that refuses overage, new sandboxes and prompts are refused once the account reaches its allowance, and nothing is charged.

## Stopped sandboxes and snapshots

A stopped sandbox does not bill compute. It keeps its disk until you delete it or until `deleteAfterStoppedSeconds` passes.

Deleting a sandbox does not delete the snapshots you saved from it. They stay until you delete them; see [Snapshots and forks](/sandbox/snapshots).

## Stop and delete sandboxes on a schedule

| Option | What happens |
|---|---|
| `idleTimeoutSeconds` | Stops the sandbox after this long with no activity. The disk is kept. |
| `maxLifetimeSeconds` | Stops the sandbox this long after create or resume, busy or not. The disk is kept. |
| `deleteAfterStoppedSeconds` | Deletes a sandbox that has been stopped this long. The default is 30 days. |

Leave a timer out and the platform's policy applies. The CLI sets `--lifetime` and `--idle-timeout`, in seconds, and defaults them to 3600 and 900.

<Tabs items={["TypeScript", "Python", "CLI"]} storageKey="sandbox-lang">
<Tabs.Tab>

```ts
import { Sandbox } from "@tangle-network/sandbox";

const client = new Sandbox({
  apiKey: process.env.TANGLE_API_KEY!,
  baseUrl: "https://sandbox.tangle.tools",
});

const box = await client.create({
  idleTimeoutSeconds: 600,
  maxLifetimeSeconds: 4 * 3600,
  deleteAfterStoppedSeconds: 86_400,
  metadata: { job: "nightly-review" },
});
try {
  const result = await box.exec("nproc");
  console.log(result.stdout);
} finally {
  await box.delete();
}
```

</Tabs.Tab>
<Tabs.Tab>

```python
import os

from tangle_sandbox import Sandbox, SandboxStatus

client = Sandbox(
    api_key=os.environ["TANGLE_API_KEY"],
    base_url="https://sandbox.tangle.tools",
)

box = client.create(
    idle_timeout_seconds=600,
    max_lifetime_seconds=4 * 3600,
    metadata={"job": "nightly-review"},
)
try:
    box.wait_for(SandboxStatus.RUNNING)
    print(box.exec("nproc").stdout)
finally:
    box.delete()
    client.close()
```

The Python SDK has no `delete_after_stopped_seconds` option. Set it by creating through `client.fetch("POST", "/v1/sandboxes", json={...})`.

```bash
tangle sandbox create --name nightly-review --idle-timeout 600 --lifetime 14400
tangle sandbox delete nightly-review --force
```

Delete every sandbox you create in a `finally` block. Timers stop a sandbox; only a delete or `deleteAfterStoppedSeconds` removes it.

### Clean up by metadata

Tag the sandboxes a job creates, then delete them all in one call. In TypeScript:

```ts
const result = await client.deleteMatching({ metadataPrefix: { job: "nightly-review" } });
console.log(result.complete);
```

It deletes only your own sandboxes whose metadata values start with the prefixes you pass. `result.complete` is `true` once every match is confirmed gone, and the call is safe to repeat.
Pass `{ cascade: true }` to delete branches with their parents. From Python or the CLI, call `POST /v1/sandboxes/delete-matching`.

## Cap what can be spent

| Scope | How to cap it |
|---|---|
| An API key | `tangle keys create ci-agents --budget-usd 25`. Calls with the key are refused once it has spent its budget. |
| A fleet | `policy.maxSpendUsd` on `client.fleets.create()`. The fleet's sandboxes charge a key with that budget; read it with `fleet.spend()`. See [Fleets](/sandbox/agents-fleet). |
| A GPU lease | `maxSpendUsd` and `maxLifetimeSeconds`, required on every lease. See [GPU leases](/sandbox/gpu-leases). |

Give each automation its own key with a budget. A runaway loop then stops at that key's budget instead of using the account's credit.
`tangle keys create` needs an API-key login; see [API keys and tokens](/sandbox/authentication#limit-what-a-key-can-do).

## See what you have spent

<Tabs items={["TypeScript", "Python", "CLI"]} storageKey="sandbox-lang">
<Tabs.Tab>

```ts
const usage = await client.usage();
const plan = await client.subscription();
console.log(usage.computeMinutes, usage.gpuCostUsd, usage.activeSandboxes);
console.log(plan.creditsAvailableUsd, plan.creditsUsedUsd);
```

</Tabs.Tab>
<Tabs.Tab>

```python
usage = client.usage()
plan = client.subscription()
print(usage, plan)
```

</Tabs.Tab>
<Tabs.Tab>

```bash
tangle usage
tangle usage --json
```

</Tabs.Tab>
</Tabs>

`usage()` covers the current UTC day: compute minutes, GPU seconds and GPU spend, and active and total sandboxes.
`subscription()` returns the plan, credit available and used, and the plan's limits. `creditsAvailableUsd` can be negative on plans that allow overage.
The [dashboard billing page](https://sandbox.tangle.tools/dashboard/billing) shows the credit balance and account activity.

One sandbox's egress this month, in TypeScript:

```ts
const egress = await box.egress.usage();
console.log(egress.bytes, egress.chargeUsd, egress.accountBytes, egress.accountIncludedBytes);
```

## Model spend per turn

When the coding agent uses the Tangle Router, `prompt()` returns what the turn's model calls cost:

```ts
const result = await box.prompt("Explain the build failure.");
console.log(result.costUsd);
```

`costUsd` is model spend only, not compute. It is `undefined` when another turn on the same sandbox overlapped this one, or when the SDK cannot read your account's ledger.
The SDK reads the ledger without extra setup when `baseUrl` is `https://sandbox.tangle.tools`.

With your own [Claude](/sandbox/cloud-agents-claude-code) or [ChatGPT](/sandbox/cloud-agents-codex) plan, model use goes to that plan and is not charged to your Tangle credit.
