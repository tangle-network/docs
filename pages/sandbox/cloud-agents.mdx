# Run a coding agent in a sandbox

Each sandbox can run a coding agent such as Claude Code, Codex, OpenCode or Pi
against a repository. The agent gets a Linux machine with a shell, git and
package managers. You send it a task from the SDK, the CLI or HTTP, check its
work yourself, and delete the sandbox when you are done.

## Fix a failing test

<Tabs items={["TypeScript", "Python", "CLI"]}>
<Tabs.Tab>
```ts
import { writeFile } from "node:fs/promises";
import { Sandbox } from "@tangle-network/sandbox";

const client = new Sandbox({
  apiKey: process.env.TANGLE_API_KEY!,
  baseUrl: "https://sandbox.tangle.tools",
});

const box = await client.create({
  git: { url: "https://github.com/tangle-network/sandbox-demo" },
  backend: { type: "claude-code" },
});
try {
  const run = await box.prompt("`npm test` fails. Find the cause and fix it.");
  if (!run.success) throw new Error(run.error);

  const tests = await box.exec("npm test");
  if (tests.exitCode !== 0) throw new Error("The tests still fail.");

  await writeFile("fix.patch", (await box.exec("git diff")).stdout);
  console.log(run.usage, run.costUsd);
} finally {
  await box.delete();
}
```
</Tabs.Tab>
<Tabs.Tab>
```python
import os

from tangle_sandbox import BackendConfig, CreateSandboxOptions, GitConfig, Sandbox

client = Sandbox(api_key=os.environ["TANGLE_API_KEY"], base_url="https://sandbox.tangle.tools")
box = client.create(
    CreateSandboxOptions(
        git=GitConfig(url="https://github.com/tangle-network/sandbox-demo"),
        backend=BackendConfig(type="claude-code"),
    )
)
box.wait_for("running")
try:
    run = box.prompt("`npm test` fails. Find the cause and fix it.")
    if not run.success:
        raise RuntimeError(run.error)
    tests = box.exec("npm test")
    print("pass" if tests.exit_code == 0 else "still failing")
    print(box.exec("git diff").stdout)
finally:
    box.delete()
    client.close()
```
</Tabs.Tab>
<Tabs.Tab>
```bash
tangle sandbox create --name fix-tests --backend claude-code \
  --git-url https://github.com/tangle-network/sandbox-demo
tangle agent prompt <sandbox-id> "\`npm test\` fails. Find the cause and fix it." --stream
tangle sandbox delete <sandbox-id> --force
```
</Tabs.Tab>
</Tabs>

A finished turn is not a finished task. `run.success` says the agent stopped
without an error; run the tests yourself to know the fix works.

`box.prompt()` never throws when the agent fails. It returns `success`,
`status`, `response`, `error`, `errorCode`, `toolInvocations`, `usage`,
`costUsd`, `traceId` and `durationMs`. It throws only for request failures,
such as a sandbox that is not running.

## Choose the coding agent

`backend.type` picks the coding agent: Claude Code (`"claude-code"`), Codex
(`"codex"`), OpenCode (`"opencode"`), Pi (`"pi"`) and others. Ask the platform which ones your account can
run:

<Tabs items={["TypeScript", "Python", "CLI"]}>
<Tabs.Tab>
```ts
const { backends } = await client.listBackends();
console.log(backends.map((backend) => backend.type));
```
</Tabs.Tab>
<Tabs.Tab>
```python
response = client.fetch("GET", "/v1/backends")
print([backend["type"] for backend in response.json()["backends"]])
```
</Tabs.Tab>
<Tabs.Tab>
```bash
curl -s https://sandbox.tangle.tools/v1/backends \
  -H "Authorization: Bearer $TANGLE_API_KEY"
```
</Tabs.Tab>
</Tabs>

Every sandbox ships the full set, so one sandbox can run a different coding
agent per turn. On the CLI, `tangle agent prompt --harness codex` runs that turn
on Codex.

## Choose how the agent pays for its model

| Credential | Set up with | Model usage is billed to |
|---|---|---|
| Tangle Router (default) | Nothing: pass no credential. | Your Tangle balance |
| Your Claude plan | [Claude Code on your Claude plan](/sandbox/cloud-agents-claude-code) | Your Claude plan |
| Your ChatGPT plan | [Codex on your ChatGPT plan](/sandbox/cloud-agents-codex) | Your ChatGPT plan |
| A GLM, Kimi or MiniMax plan | [Coding plans](/sandbox/cloud-agents-coding-plans) | That provider |

Sandbox compute is billed by Tangle in every case. See
[pricing and spend](/sandbox/cost).

On the Router, set the model with `backend.model.model`; Claude Code, Codex and
OpenCode all take it. The models your key
can run are listed by `GET /v1/router-models` with your Sandbox key, and on the
[model list](/gateway/models).

```ts
const box = await client.create({
  backend: { type: "opencode", model: { model: "<model-id>" } },
});
```

A credential can also stay outside the sandbox entirely: with proxy custody the
sandbox holds a placeholder and the network proxy adds the real value to
matching requests. See [Secrets](/sandbox/secrets).

## Watch it work

`streamPrompt()` yields events while the agent thinks, edits files and runs
commands. `applySandboxEventText()` folds them into the response text the same
way `prompt()` does:

```ts
import { applySandboxEventText } from "@tangle-network/sandbox";

let text: string | undefined;
for await (const event of box.streamPrompt("Now add a regression test.")) {
  text = applySandboxEventText(text, event);
  if (event.type === "result") console.log(text);
}
```

`getSandboxEventText(event)` returns the text one event carries. Tool calls
arrive as `message.part.updated` events whose part has `type: "tool"`.
[Stream output](/sandbox/streaming) lists every event type.

## Pick it up later

The sandbox and its conversation outlive your process. Keep the sandbox id and
the session id, then continue from anywhere:

```ts
const again = await client.get(sandboxId);
if (!again) throw new Error("The sandbox was deleted.");
await again.session("fix-tests").prompt("Open a pull request with the fix.");
```

A stopped sandbox must be resumed first. [Sessions](/sandbox/sessions) covers
resuming, detached turns and safe retries.

From a terminal, `tangle agent prompt <sandbox-id> "..." --session fix-tests`
continues the same session. `tangle ssh <sandbox-id>` opens a shell beside the
agent when the sandbox was created with `--ssh`. The
[dashboard](https://sandbox.tangle.tools/dashboard) shows each session live.
To drive the agent's own terminal UI, use [interactive mode](/sandbox/interactive).

## Run many at once

Turns in one session run one at a time. Sessions in one sandbox, and separate
sandboxes, run side by side. Your plan caps how many sandboxes run at once:
`client.subscription()` returns `maxConcurrentSandboxes`, where `0` means no
cap. [Limits](/sandbox/limits) lists the values, and [Fleets](/sandbox/agents-fleet)
run many agents under one budget.

## Spin it down

Delete the sandbox in `finally`, as the examples above do. `delete()` is
permanent. `idleTimeoutSeconds` stops a sandbox nobody is using and
`maxLifetimeSeconds` caps how long it runs, but a stopped sandbox still exists
until you delete it. See [Create, stop and delete](/sandbox/lifecycle).
