# Sessions, backends and intelligence routes

Create and stream coding-agent sessions, approve plans, list the coding agents and models your key can use, and request intelligence reports.

Every route is on `https://sandbox.tangle.tools` and takes your account API key as `Authorization: Bearer <key>` unless it says otherwise. Errors use the shape in [Error codes](/sandbox/errors).
This page is generated from the [OpenAPI document](/sandbox-openapi.json), which also has every response schema.

## Sessions

|---|---|
| `POST /v1/session/{sessionId}/broadcast` | Broadcast an event to a session |
| `PUT /v1/session/{sessionId}/mapping` | Map a session to its runtime session |
| `DELETE /v1/session/{sessionId}/mapping` | Remove a session's runtime mapping |
| `POST /v1/sessions` | Create a session |

### Broadcast an event to a session

`POST /v1/session/{sessionId}/broadcast`

Sends an event to the caller's connected WebSocket session. If the session is not connected, the event is buffered for delivery on connect. success reports whether the event was delivered or buffered.

| Parameter | In | Required | Type | Description |
|---|---|---|---|---|
| `sessionId` | path | Yes | string | Session ID |

Request body (`application/json`):

| Field | Type | Required | Description |
|---|---|---|---|
| `type` | string | Yes | Event type. |
| `id` | string | No | Event ID the receiver can use to deduplicate. |
| `data` | object | No | Event payload. |
| `channel` | string | No | Deliver only to subscribers of this channel. |

| Status | Meaning |
|---|---|
| 200 | The broadcast result |
| 400 | The session ID or the body is invalid (VALIDATION_ERROR, INVALID_SESSION_ID) |
| 401 | Missing or invalid credential |
| 403 | The credential is restricted to its own sandbox (SANDBOX_KEY_RESOURCE_FORBIDDEN) |
| 503 | The sandbox service did not answer; retry shortly |

### Map a session to its runtime session

`PUT /v1/session/{sessionId}/mapping`

Registers which runtime session serves the session ID, so session events are filtered and delivered to the right subscribers.

| Parameter | In | Required | Type | Description |
|---|---|---|---|---|
| `sessionId` | path | Yes | string | Session ID |

Request body (`application/json`):

| Field | Type | Required | Description |
|---|---|---|---|
| `sidecarSessionId` | string | Yes | The runtime's own session ID (a UUID). |
| `sidecarId` | string | No | Container ID, for direct routing. |
| `projectRef` | string | No | Project reference, for stale-runtime checks. |

| Status | Meaning |
|---|---|
| 200 | The mapping was recorded |
| 400 | The session ID or the body is invalid (VALIDATION_ERROR, INVALID_SESSION_ID) |
| 401 | Missing or invalid credential |
| 403 | The credential is restricted to its own sandbox (SANDBOX_KEY_RESOURCE_FORBIDDEN) |
| 404 | The mapping was rejected |
| 410 | The runtime is gone and must be reprovisioned |
| 503 | The sandbox service did not answer; retry shortly |

`POST /v1/plan-submissions`

Authenticated by the x-tangle-plan-submission-credential header, not by a bearer token. A repeat with the same sourceTurnId and sourceToolCallId returns the same plan. Approvers cannot see the plan until it is confirmed. A session whose backend isolates profile secrets is refused.

### Approve or reject a plan

`POST /v1/sandboxes/{projectRef}/agent-sessions/{agentSessionId}/plans/{planId}/decision`

Needs write access to the sandbox; a team viewer is refused. Repeating the same decision answers idempotent: true. Send followUp \{ mode: "caller" \} to receive the follow-up turn's resume credential instead of having the service start the turn.

| Parameter | In | Required | Type | Description |
|---|---|---|---|---|
| `projectRef` | path | Yes | string | Sandbox ID |
| `agentSessionId` | path | Yes | string | Agent session ID |
| `planId` | path | Yes | string | Plan ID |

Request body (`application/json`): one of 2 shapes; see the [OpenAPI document](/sandbox-openapi.json).

| Status | Meaning |
|---|---|
| 200 | Decision recorded |
| 400 | Invalid decision (INVALID_REQUEST, PLAN_REJECTION_FEEDBACK_REQUIRED, PLAN_APPROVAL_FEEDBACK_FORBIDDEN) |
| 403 | The credential or team role cannot decide this plan (INSUFFICIENT_ROLE, PLAN_DECISION_ACTOR_INVALID) |
| 404 | Plan not found (PLAN_NOT_FOUND) |
| 409 | The plan cannot be decided in its current state, or its caller follow-up is leased (PLAN_SUPERSEDED, PLAN_WITHDRAWN, PLAN_ALREADY_DECIDED, PLAN_OUTBOX_LEASE_LOST) |
| 413 | The request body is over the proxy limit |
| 503 | Caller follow-up admission is not configured (PLAN_FOLLOWUP_UNAVAILABLE) |

### List available agent backends

`GET /v1/backends`

Returns the per-backend capability registry (streaming, tool use, reasoning, multimodal, imageInput, MCP, sessions, interactions) and whether a backend runs only on the caller's own credential. Profiles are supplied inline on execution and provisioning requests.

| Status | Meaning |
|---|---|
| 200 | Backends retrieved successfully |
| 500 | Internal error |

### List the Router model catalog

`GET /v1/router-models`

The Tangle Router's `GET /v1/models` rows, read with the caller's managed Router key, so the list is the models this caller can run.

| Status | Meaning |
|---|---|
| 200 | Router model catalog |
| 502 | The Router refused or failed |
| 503 | No Router key can be minted |
