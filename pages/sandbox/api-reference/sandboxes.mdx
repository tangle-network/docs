# Sandboxes and GPU routes

Create and manage sandboxes, their snapshots, branches and egress rules, and attach GPU leases.

Every route is on `https://sandbox.tangle.tools` and takes your account API key as `Authorization: Bearer <key>` unless it says otherwise. Errors use the shape in [Error codes](/sandbox/errors).
This page is generated from the [OpenAPI document](/sandbox-openapi.json), which also has every response schema.

### Delete a sandbox

`DELETE /v1/sandboxes/{id}`

Deletes the sandbox. A sandbox with live branch children is refused (409 CHILDREN_EXIST) unless `cascade=true`, which deletes the whole lineage children-first. Platform-managed snapshot repositories are reclaimed after the deleted-retention window for internal accounts only; customer repositories remain until explicitly deleted by their owner. Preservation holds and active exports/restores are honored. With `wait=false` it may instead answer 202 as soon as the delete is durably accepted: poll `operation.statusUrl` (or `Location`) until the operation is `succeeded` (with `result.deleted`) or `failed`. The runtime runs and bills until the delete kills it. An `Idempotency-Key` names the delete for a retry whose 202 was lost. With `until=removed`, that status URL keeps polling through physical reclaim. Cascades keep the synchronous answer; a 200 means the delete finished.

|---|---|---|---|---|
| `id` | path | Yes | string | Sandbox ID |
| `retireCreate` | query | No | "true" \| "false" |  |
| `run` | query | No | string |  |
| `expectedCellId` | query | No | string |  |
| `billingOwnerId` | query | No | string |  |
| `cascade` | query | No | "true" \| "false" |  |
| `until` | query | No | "removed" |  |
| `wait` | query | No | "true" \| "false" |  |

| Status | Meaning |
|---|---|

### List the hosts a sandbox reached

`GET /v1/sandboxes/{id}/egress/activity`

Every destination this sandbox's egress proxy allowed or refused in the inspected window, and whether that observation can be trusted. This is the OPPOSITE question to /egress/denials, and unlike that route it is deliberately not best-effort: it exists to support the negative claim 'this sandbox reached nothing', which an empty list cannot carry on its own. `destinations: []` with `complete: true` is evidence; `destinations: []` with `complete: false` is an absence of evidence, and `incompleteReasons` names what was missing. A hop that could not reach the host reports `hop-unreachable` rather than an empty list, so an unreadable path can never be read as a clean sandbox.

| `id` | path | Yes | string | Sandbox ID |

| 403 | Forbidden |
| 404 | Sandbox not found |
| 409 | Egress is not enabled for this sandbox |

### Get an MCP endpoint for this sandbox

`GET /v1/sandboxes/{id}/mcp`

Returns a paste-able MCP host config (Claude Desktop, Cursor, claude-code, codex, …) plus a freshly-minted, capability-scoped JWT. The token is short-lived and can ONLY call MCP routes; it cannot reach admin endpoints (/exec, /files, …) on the sandbox. Call again to rotate.
