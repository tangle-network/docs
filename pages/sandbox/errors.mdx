# Error codes and how to fix them

Every failed call carries a code. Branch on the code, not on the message or an error class.
This page shows where the code appears in each client, which errors to retry, and what every code means.

## Read the code in your client

<Tabs items={["TypeScript", "Python", "CLI", "REST"]} storageKey="sandbox-lang">
<Tabs.Tab>

The SDK throws `SandboxError`.

```ts
import { SandboxError } from "@tangle-network/sandbox";

try {
  await box.exec("npm test");
} catch (error) {
  if (!(error instanceof SandboxError)) throw error;
  if (error.catalogCode === "INVALID_STATE") {
    await box.resume();
  } else {
    console.error(error.code, error.status, error.retryable, error.nextStep, error.requestId);
    throw error;
  }
}
```

| Field | Meaning |
|---|---|
| `code` | The code the server sent, such as `CHILDREN_EXIST`. |
| `catalogCode` | The nearest code in the table below. Branch on this when `code` is not in the table. |
| `status` | The HTTP status. |
| `retryable` | Whether repeating the same request can succeed. |
| `nextStep` | The fix, in one sentence. |
| `requestId`, `traceId` | Ids to quote when you contact support. |
| `retryAfterMs` | How long the server asked you to wait, when it did. |

`AuthError`, `NotFoundError`, `StateError`, `ValidationError` and the other subclasses still work but are deprecated. Read `code` or `catalogCode` instead.

</Tabs.Tab>
<Tabs.Tab>

The SDK raises `SandboxError`.

```python
from tangle_sandbox import SandboxError

try:
    box.exec("npm test")
except SandboxError as error:
    print(error.code, error.status, error.retryable, error.next_step)
    raise
```

`code`, `status`, `retryable` and `next_step` come from the table below.
The SDK raises the older alias classes, such as `AuthError`, `StateError` and `TimeoutError`, which are all `SandboxError` subclasses; catch `SandboxError` and read `code`.
A few argument checks raise a plain `ValueError` before any request is sent.

</Tabs.Tab>
<Tabs.Tab>

Without `--json`, the CLI prints one error to stderr with its cause, the next step and a command that fixes it:

```text
✗ <what failed> (HTTP 409) — <cause>
  → next: <next step>
  → run: <command>
```

With `--json`, it prints an error document on stdout:

```json
{
  "ok": false,
  "error": {
    "code": "INVALID_STATE",
    "message": "...",
    "nextStep": "...",
    "retryable": false,
    "fix": { "command": "..." },
    "requestId": "...",
    "status": 409
  }
}
```

The exit code tells a script what kind of failure it was; see [CLI exit codes](#cli-exit-codes).

</Tabs.Tab>
<Tabs.Tab>

Most routes answer an error with this body:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request",
    "nextStep": "Fix the field the message names and send the request again.",
    "details": { "issues": [{ "path": "resources.cpuCores", "message": "..." }] }
  }
}
```

Some routes answer `{ "error": "<message>", "code": "<CODE>" }` with extra fields beside `code`, such as `children` on `CHILDREN_EXIST`.
Read `error.code` when `error` is an object, otherwise read `code`.

</Tabs.Tab>
</Tabs>

## Retry the right errors

Retry only when the code's **Retry** column says Yes, and wait for `Retry-After` when the response has one.

| Client | What it retries for you |
|---|---|
| TypeScript SDK | Up to 4 attempts for `GET`, `HEAD`, `OPTIONS`, `PUT`, `DELETE` and any request with an `Idempotency-Key`, on 502, 503, 504, and 429 with `Retry-After`. It never retries a code the table marks No. A request that provably never reached the server is retried whatever its method. Waits between attempts are at most 4 seconds. |
| Python SDK | `GET`, `HEAD`, `PUT`, `DELETE` and `OPTIONS` on 429, 502, 503 and 504 when the code is retryable, waiting `Retry-After` or backing off from 1 second. Connection failures are retried for any method. |
| CLI | Uses the TypeScript SDK's retries. |

Both SDKs send an `Idempotency-Key` with every create and reuse it when they send the create again.
When no host has room (`CAPACITY_EXHAUSTED`, `HOST_PRESSURE`, `PLACEMENT_WARMING`), they send the same create again for up to 150 seconds, within your request timeout.
The second request joins the first, so you never get two sandboxes.
In TypeScript, `create({ retry: { capacity: false } })` returns `CAPACITY_EXHAUSTED` at once so you can decide when to try again.

If you send creates yourself, set your own `Idempotency-Key` header and reuse it for every retry of the same create:

```bash
curl -s https://sandbox.tangle.tools/v1/sandboxes \
  -H "Authorization: Bearer $TANGLE_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: build-4821" \
  -d '{"name":"build-4821"}'
```

## Errors you will see most

<Callout>
**`INVALID_STATE` (409) on a command or prompt.** The sandbox is stopped. Call `box.resume()` and try again. The CLI resumes a stopped sandbox for you before `exec`, `ssh`, `fs`, `git`, `process` and `agent prompt`.
</Callout>

- **`CAPACITY_EXHAUSTED`, `HOST_PRESSURE` (503) on create.** No host has room right now. The SDKs retry for you; see [Retry the right errors](#retry-the-right-errors).
- **`QUOTA_EXCEEDED`, `CONCURRENT_LIMIT` (429) on create.** You reached your plan's limit of running sandboxes. Stop or delete one, or raise your plan. See [Limits and timeouts](/sandbox/limits).
- **`RESOURCES_EXCEED_LIMIT` (400) on create.** The CPU, memory or disk you named is above your account's ceiling. The response names the field, the requested and the allowed value. Read your ceiling with `client.shapes()`.
- **`COMPLIANCE_NOT_ENTITLED` (403).** The create asked for `compliance: { hipaa: true }` and the key has no HIPAA entitlement.
- **`COMPLIANCE_CAPACITY_UNAVAILABLE`, `COMPLIANCE_CELL_UNAVAILABLE` (503).** No HIPAA capacity can take the sandbox now, and it is never placed anywhere else. Retry the first after `Retry-After`; retry the second later, and contact support if it persists.
- **`CHILDREN_EXIST` (409) on delete.** The sandbox has live branches. Delete them first, or delete the whole family with `DELETE /v1/sandboxes/{id}?cascade=true` or `client.deleteMatching(filter, { cascade: true })`.
- **`IMAGE_BUILDS_DISABLED` (403) on `POST /v1/images`.** The hosted service does not build images. Start from an environment or a pushed image reference; see [Templates and images](/sandbox/templates-gallery).
- **`GPU_PROVIDER_NOT_CONFIGURED` (503).** No GPU provider is set up for the service you called. Create the sandbox without a GPU.
- **`PROFILE_INVALID` (CLI exit 65).** `tangle agent profile validate` or a command that loads an AgentProfile found it invalid. The message names the field.

| Status | Code | Meaning | What to do |

| 400 | `NATIVE_AUTH_INVALID` | The subscription credential for Claude Code or Codex could not be read. | Check the stored secret named in `cliAuth`. |
| 400 | `RESOURCES_EXCEED_LIMIT` | The size you named is above your account's ceiling. | Ask for less, or omit `resources` to get the clamped default. |
| 400 | `SECRET_NOT_FOUND` | The create names a stored secret that does not exist. `missingSecrets` lists them. | Create the secret, or remove it from `secrets`. |
| 402 | `ACCELERATOR_REQUIRES_PAID_PLAN` | GPU sandboxes need a paid plan with usage billing. | Change plan at [id.tangle.tools](https://id.tangle.tools/app/billing). |
| 402 | `INSUFFICIENT_BALANCE` | The account owes money or has no balance. | Add credit at [id.tangle.tools](https://id.tangle.tools/app/billing). |
| 402 | `SUBSCRIPTION_INACTIVE` | The account has no active subscription. | Choose a plan at [id.tangle.tools](https://id.tangle.tools/app/billing). |
| 403 | `IMAGE_BUILDS_DISABLED` | The hosted service does not build images through the API. | Use an environment or a pushed image reference. |
| 403 | `TIER_REQUIRED` | A startup script with `runAsRoot` needs a Pro or Enterprise plan. | Remove `runAsRoot` or change plan. |
| 404 | `PUBLIC_TEMPLATE_NOT_FOUND` | The public template does not exist. | Check the id or slug with `GET /v1/public-templates`. |
| 404 | `TEMPLATE_NOT_FOUND` | The template does not exist or belongs to another account. | Check the id with `GET /v1/templates`. |
| 409 | `CHILDREN_EXIST` | The sandbox has live branches. `children` lists them. | Delete the branches first, or pass `cascade=true`. |
| 409 | `FINAL_SUSPEND_UNCONFIRMED` | The delete needs a confirmed final save of the sandbox, and there is none. | Retry the delete. Contact support with the request id if it repeats. |
| 409 | `IDEMPOTENCY_KEY_REUSED` | The `Idempotency-Key` already names a different delete of this sandbox. | Use a new key for a different request. |
| 409 | `IDEMPOTENT_CREATE_CONFLICT` | An earlier create with this key still holds the sandbox. | Inspect that sandbox, or create with a new `Idempotency-Key`. |
| 409 | `RETENTION_HOLD` | A retention hold blocks this delete. The response names the hold and its `expiresAt`, when it has one. | Delete after the hold expires, or contact support. |
| 429 | `CONCURRENT_LIMIT` | Your plan's limit of running sandboxes is reached. | Stop or delete sandboxes, or raise your plan. |
| 429 | `PLATFORM_RATE_LIMITED` | Account checks for this create were rate-limited. | Retry after `Retry-After`. |
| 502 | `SANDBOX_CREATE_READINESS_FAILED` | TypeScript SDK: the sandbox was created but did not reach `running` in time. The error carries the sandbox id. | Read or delete that sandbox, or create again with the same `idempotencyKey`. |
| 502 | `router_catalog_unavailable` | The Tangle Router refused or failed the model list. | Retry later. |
| 503 | `IDEMPOTENT_CREATE_IN_PROGRESS` | An earlier create with this key is still running. | Retry after `Retry-After`; you get the same sandbox. |
| 503 | `SANDBOX_BILLING_STATE_UNAVAILABLE` | The sandbox's billing state could not be read. | Retry the request. |
| 503 | `SPARE_CAPACITY_UNAVAILABLE` | A create limited to spare capacity found none free. It is not placed elsewhere. | Retry later. |

## CLI exit codes

| Exit code | Meaning |
|---|---|
| 0 | Success. |
| 1 | The command failed. `fleet` and `batch` exit 1 when any member failed. |
| 2 | `tangle agent connect` was given an unknown framework. |
| 64 | Usage error: an unknown command or option, or a missing parameter. |
| 65 | An invalid definition, such as an AgentProfile (`PROFILE_INVALID`), a graph, a workflow input file or a request that failed validation. |
| 69 | Something the command needs is unavailable: a coding agent that is not installed, an unreachable MCP server or no network. |
| 75 | Temporary: a rate limit or a seat limit. Retry later. |
| 77 | Sign in again: the credential expired, was refused (any HTTP 401) or belongs to another service. |
| 78 | Configuration: a subscription is required, the model was not found or does not match its provider. |
| 130 | Stopped with Ctrl-C. |
| 143 | An interactive agent session ended with SIGTERM. |
| Remote exit code | `tangle exec`, `tangle run`, `tangle sandbox gpu run` and `tangle process spawn --blocking` exit with the remote command's code. `tangle ssh` exits with ssh's code. |
